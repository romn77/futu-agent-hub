# Position lifecycle and journal contract

Lifecycle analysis compares the current immutable snapshot with private, user-authored records. It
does not infer investment intent from price, profit, loss, security name, or role metadata.

## Deterministic states

Every non-zero economic position appears exactly once. A missing record is `UNCONFIGURED` with
`UNREVIEWED` thesis status. A configured current position is `INTACT` unless evidenced findings apply.
Precedence is `BROKEN`, `ROLE_DRIFT`, `WEIGHT_DRIFT`, `HORIZON_DRIFT`, `WEAKENING`, then
`STRENGTHENING`. An absent recorded position is `EXITED`. A current position whose record says
`EXITED` is `BROKEN` because the user fact conflicts with current holdings.

Target bounds are inclusive. Supported horizons are `N` or `N-M` days, weeks, months, or years. The
upper value is authoritative; months equal 30 days and years equal 365 days. Dates compare against
the snapshot's timezone-aware `as_of` calendar date. Unsupported horizons fail rather than guess.

`SATELLITE` role drift requires weight at or above 10% in at least three immutable snapshots spanning
at least 30 days. Without that evidence the report records the check as unavailable/partial. Thesis
states require an explicit user review input and never derive from returns.

Every eligible history snapshot records the full snapshot ID, timezone-aware `as_of`, canonical
market-qualified identity, explicit presence, and a Decimal weight only when present. An intervening
absence interrupts persistence and makes role evidence partial rather than silently disappearing.
Inputs are fully schema/identity/financial-semantics
validated, deduplicated, and stably sorted. Observations before the record's `opened_at` date or after
the current snapshot `as_of` are excluded with explicit coverage and quality notes. Runtime report
validation recomputes the eligible window, minimum count, 30-day duration, threshold persistence,
history availability, and `ROLE_DRIFT` result from the serialized evidence; report-ID recomputation
cannot turn an insufficient window into an authoritative role-drift finding.

The current source and every history item use canonical timestamped IDs whose encoded timestamp must
equal `as_of`; lifecycle, risk, and portfolio outputs agree on source ID and time. Long-only weights
must be finite and between zero and one. Snapshot, configuration-record, observation, operation, and
injected wall-clock budgets fail closed before unbounded work; accepted snapshots are indexed once.

Human and Markdown views include lifecycle `as_of`, source snapshot, status, coverage, structured
quality reasons, role/status, current and target bounds, dates/horizon, thesis review status, every
finding and history provenance. They also display the sanitized user-authored original thesis,
invalidation conditions, review triggers, and notes, each explicitly marked `USER_CONFIG` and
`system inferred: false`; none of these facts is generated by the analyzer. JSON embeds the same
authoritative sanitized thesis text and binds it to its exact SHA-256 digest and character count.
Runtime validation recomputes that binding and the configured/unconfigured/thesis-status contract.

Top-level `data_quality_status`, structured `data_quality_reasons`, and canonical notes are derived
from `coverage.history.status`, every future/duplicate/pre-open exclusion, insufficient evidence,
and every position quality note. Any partial/unavailable evidence makes the top-level report partial
(or unavailable for a module failure); removing those reasons or relabeling the report complete is a
semantic error even if the full-body report ID is recomputed.

JSON remains the strict private authoritative artifact and all displayed untrusted fields are
credential/identifier/control scrubbed and Markdown escaped. Saved lifecycle and comprehensive
reports stay beneath private `PORTFOLIO_AGENT_HOME` paths. `--no-save` is intentionally self-contained
and prints this private user configuration directly to the requesting terminal/stdout; users should
redirect it only to a private file or trusted consumer.

## Private persistence

`PORTFOLIO_AGENT_HOME` defaults to `~/.moomoo-portfolio-agent` and must be outside the repository.
On POSIX the home and state directories use mode `0700`, files use `0600`, and reads/writes reject
symlinks and hard links. Anchored descriptors, no-follow opens, inode revalidation, no-overwrite
links, locking, fsync, and bounded reads protect the local contract. Platforms without equivalent
handle-level reparse/no-follow and interprocess locking disable repository mutation, append, and
repository reads with `UNSUPPORTED_PLATFORM_SECURITY`.

Snapshots are immutable and content-addressed under `snapshots/YYYY/MM`. Journal decisions and
analysis references are explicit `decisions.jsonl` and `analyses.jsonl` appends. Each record has a
full-body identity and previous-record hash. Existing records are never silently repaired.
Snapshot enumeration validates exact year/month placement, legal months, entry/byte budgets, and
descriptor permissions before parsing. Journal JSON is canonical and duplicate-key-safe. Every CLI
multi-file bundle publishes artifacts, fsyncs the directory, then publishes `manifest.json` and
fsyncs again. The manifest binds a real-calendar canonical source snapshot ID and `as_of`, report
ID, and every artifact's byte size and SHA-256. Validation uses anchored no-follow descriptors,
bounded streaming digests, descriptor mode/link checks, aggregate budgets, and post-read
inode/parent revalidation. Missing manifests, unexpected artifacts, unsafe files, anchor changes,
or size/digest mismatches are `INCOMPLETE`. Repository consumer limits and lifecycle
shape/node/observation/operation/wall limits apply before bulk parsing or JSON Schema work.

Comprehensive analysis treats lifecycle as an independent local module. Invalid or inaccessible
lifecycle configuration produces an `UNAVAILABLE` lifecycle section while the risk report remains
valid and fully attributable to the same `source_snapshot_id`.
An empty history is `HISTORY_UNAVAILABLE`; a corrupt or unsafe repository becomes sanitized
structured `HISTORY_INVALID` evidence attached to top-level and per-position quality instead of being
silently treated as empty.
