## Implementation and evidence boundary

`evals/policy_context.py`装配12份默认完整规则与显式选择的条件规则，保留UTF-8字节、
逐文档SHA-256和bundle ID。`evals/run_host_context.py`仅接受冻结合成工作区，
复核正文、请求和payload后经既有Codex CLI stdin提交。输入不是摘要，原文件仍可读取。
规则、账户/交易引擎、schemas和默认Skill入口未改动。

交付回执证明送入CLI的确切字节，不证明远端模型记忆或隐藏的服务端revision。
原`audit.json`和必读文件检查保留；宿主检查单列完整输入证明，不伪造文件读取。
重读计数依照真实命令输出：预加载正文第一次再次输出即计重读，未预加载的条件规则或
四份白名单研究方法允许首次读取。部分、失败、未知或冲突事件不会作为干净复用通过。
这是输出审计，不是操作系统访问追踪，也不是任意Python代码的安全沙箱。

本地CLI `0.154.0`支持stdin/JSONL/read-only/ephemeral；实际用法与
[官方非交互模式文档](https://learn.chatgpt.com/docs/non-interactive-mode)一致。
请求模型`gpt-6-astra`、reasoning `medium`，600秒/8MiB预算，每份独立进程，最多并发2。
launcher哈希固定，先验证哈希再执行版本查询；无法验证后端模型revision相同。

## Outcome and remaining scope

本轮有界可行性验证通过：7份报告、0次模型重试；5份宿主报告均满足完整交付、零完整重读、
无不可核验访问与独立内容门槛。独立审查还核验了实际公共请求、一次采集、研究/估值预算。
盲审材料只包含账户/研究/计算回执，不含完整指令访问轨迹；完整交付与重读证据由单独的
宿主回执、冻结正文和原始事件提供，不把审查者的政策目录当成读取证明。

该结果不等于生产验收、普遍零重读保证、费用下降或研究质量提升。模型服务端revision
未知；三个新场景仅各一次，没有新的配对质量比较。复杂基金、完整实时技术数据、实盘
源冲突和长期运行仍未由本轮覆盖。原型不改变账户/交易引擎或生产默认加载，也未推送/合并。
历史AC-17及R2/R3失败结论保持不变。生产接入、真实宿主权限边界与持续回归属于后续范围。

## Reproduction

从组件Git checkout调用`.venv/bin/python evals/run_host_context.py prepare --source <合成输入目录>
--output <新目录> --mode host-context`，根据请求显式添加`--policy <白名单条件路径>`。
然后`execute --output <新目录> --cli <既有CLI绝对路径> --cli-sha256 <已核验哈希>`。
`--mode filesystem`提供同请求的文件加载对照。输入目录必须由现有合成准备器生成，
包含fixture helper；本入口不是实盘分析启动器。评分量表必须留在模型工作区之外。
