# Portfolio Analyst 进度记录（2026-09-13）

本次保存账户数据、分析证据与评测工具的开发进度，以及用户画像的已确认方向和设计审查结论。
画像读取仍处于设计阶段：当前 CLI 尚未实现 `--profile-dir`，本记录不代表画像功能已经交付。

## 当前代码进度

- 账户选择：仅在一个符合条件的账户存在时自动选择；支持显式 `--acc-id`，所选账户读取不完整时停止快照生成。
- NAV：新快照使用 OpenD `funds.total_assets`，保留逐账户 NAV 与币种换算证据；兼容旧版快照的原始内容身份和估值口径。
- 源字段：保留缺失现金、成本、价格、可卖数量等字段的未知状态，并保留源持仓币种；不会从其他汇总值补算缺失事实。
- 证券类型：增加有超时和输出上限的只读静态元数据查询；分类数据缺失或无效时按影响范围降级。
- 分析编排：校验快照和 risk、technical、options 的结构、语义与证据绑定；局部模块失效保留其他可靠结果。
- 下游兼容：风险、期权、绩效归因、模拟和报告处理新的 NAV 来源与可空字段；期权 Greeks 完整性与无关字段缺失分别评估。
- 研究与评测：补充宿主网页工具能力契约，以及基于合成数据、独立执行记录的 Codex 评测生产器和测试。

## 画像已确认方向

- 面向个人当前持仓分析，用户可指定一个保存 Markdown 画像的目录。
- 使用显式 `--profile-dir`，不依赖全局环境变量自动选择画像。
- 未提供画像时采用“中性观察型”，不假设个人投资期限、风险承受能力或仓位上限。
- 关注股票与板块占比、风险暴露、基本面、技术面、同题材替代比较及组合进攻性。

## 设计审查后的建议（尚未实施）

1. 保留易维护的 Markdown 描述；区分可计算约束、投资偏好与风险描述。固定标题本身不能消除语义歧义，严格数值约束可使用可选结构化区块。
2. 画像字段缺失时保留其他有效信息；单项冲突按项停用。指定文件加载失败应明确说明，与未提供画像区分。
3. 定义画像与现有 `config/risk_policy.json` 的规则优先级；同一含义和口径的规则应由计算和报告一致使用，不能只在文字中覆盖旧阈值。
4. 区分“约束已加载”和“约束可验证”：现金缺失、题材分类不足、核心/卫星角色不明或尚无回撤分析时，不能给出虚假的符合结论。
5. 题材上限明确使用完整计入还是均分计入口径，说明 NAV 分母和分类覆盖。期权市值不能冒充方向敞口。
6. 中性观察型仍可依据证据解释组合风格；是否超出个人风险承受范围需要画像支持。
7. 同题材候选比较承接已明确的分析需求，另行定义研究预算和数据覆盖；现有技术 CLI 只接受已持有美股/ETF，画像读取不会自动扩展该能力。
8. 拟在 `scripts/current_analysis.py` 接入目录参数，只读取固定 `profile.md`，不递归扫描或回写；定义读取上限、编码、路径处理、单次内容绑定和画像隐私规则。
9. 报告显示画像加载状态、生效规则来源、实际核对结果及无法核对原因；画像中的目标或上限本身不构成模拟或交易指令。

## 后续验收重点

- 无画像仍能完成全仓分析并解释组合风格。
- 少量有效偏好可以生效，单个错误字段不会丢弃其他独立有效项。
- 旧配置与画像冲突时，工具计算与最终报告使用同一规则及来源。
- 分类、现金、角色或其他必要证据不足时，显示未知或不支持，而非通过。
- 区分画像里的风险上限与本轮明确请求的调仓模拟目标。
- 画像内容和私有路径不进入网页研究请求；一次分析绑定同一份画像内容。
