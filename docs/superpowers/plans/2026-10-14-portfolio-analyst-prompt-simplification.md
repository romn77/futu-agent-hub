# Portfolio Analyst Prompt Quality and Simplification Plan

日期：2026-10-14。修订：3，加入顾问复核与三类进取型需求。状态：用户已授权实施。
需求以 [spec](../specs/2026-10-14-portfolio-analyst-prompt-simplification.md) 为准；
逐项状态和验收记录只在 [tasks/todo.md](../../../tasks/todo.md) 维护。

## 方案

保留 12 个默认文件的路径和职责入口，在原位置缩短执行说明；把估值计算细则按需加载，
把 helper 清理与金融工具推导放入维护参考。模型继续读取一次账户、使用同一组计算结果，
并按实际集合明确深研与技术覆盖差异。目标是基础必读 ≤ 6,900 词且 ≤ 54,512 字符。

同时增加期限适配、风险轻重、研究资源和单位核验；在明确主动顾问请求下提出机会优先级、
调整方向/条件仓位方案、新候选和事件/进攻策略。已确认会话偏好持续复用，无该偏好的普通诊断保持原范围；主动顾问最多增加
2 个新候选和 1 种特殊策略，完整估值全报告共享 2 个默认名额。只改变 prompt 层深研分配，
技术选择和账户引擎不改。用冻结数据的报告盲评验证效果；9 个质量场景各做两个重复，
双版本共 36 份报告，加原 9 次行为回归，初次正式验收为 45 次模型执行。
这些调用属于本次授权的开发验收，按准备、冻结、执行和独立复核依次完成。

不以减少文件数为目标，不新增自动调度器，不扩展技术指标引擎。原核心模型评测的 12 份
必读门禁因此可以保持；文档迁移对应的测试位置更新不能变成放宽执行证据要求。

## 检查点

| 检查点 | 通过条件 | 失败时 |
|---|---|---|
| A，PS-02–03 后 | 估值校验完整、触发前读取；helper 行为与 fatal/局部失败不变 | 在所属切片修复，不继续批量删文案 |
| B，PS-04–05 后 | 所有原实现细节有维护参考、规则无冲突、相关测试通过 | 恢复遗漏条款或纠正归属 |
| C，PS-06–07 后 | 稳定章节与全部持仓保留；9 个深研不承诺 9 个技术覆盖 | 修正相应契约，不扩展计算引擎 |
| Q，RQ-08 后 | FR-08–17 覆盖；明确机会/建议/新研究与执行分离，相关预算和单位核验可检查 | 修复所属规则，不用扩大仓位/杠杆冒充质量 |
| Regression，PS-10 后 | AC-01–12 有证据，质量规则通过开发样本检查 | 此时只能声称行为回归通过，不能声称研究提升 |
| Final，RQ-04 后 | AC-01–23 和双版本质量门槛都有证据 | 分别报告三类完成状态；不足则明确未证明提升 |

## 验证安排

1. PS-01 使用实施时实际工作区固定基线。首次规划 `d823b98`、修订时 `9e9c491` 均不自动等于未来起点。
   共享目录若在测试过程中发生变化，先识别具体差异；需要隔离时只复制已确认的任务输入，
   不回滚其他会话的文件，不把无 Git 元数据造成的 fixture 故障误报为产品回归。
2. RQ-01 必须先于生产 prompt 改动，冻结完整 B0、Q01–Q09 输入、证据检查表和评分标准；
   没有可比较的旧版就不能完成改善评测。仅准备副本和输入，不在此任务调用模型。
3. 每个文本切片运行 prompt 架构测试，并按移动内容运行 helper/technical 或 eval parser 回归。
   不对同义句写机械逐字测试，也不删除行为断言。
4. PS-08 在 RQ-07/08 后核验所有相对链接、D0 加全部默认质量规则的计数与 INV 迁移表；
   条件顾问文档另记实际读取成本。FR-13/17 是明确的行为调整，其余账户/报告不变量不得退化。
5. PS-09 准备输入但不调用真实账户。当前 US.NVDA 已满足“持有、未入 T、有研究输入”，优先
   复用它；若实施时 fixture 已变化，重新确认。当前大组合选中 8 个但技术记录全部 UNAVAILABLE，
   扩围研究的 NVDA/TSLA 未入选；必须区分两类缺口，不把入选数量作为有指标的覆盖数。
6. PS-10 运行原 3 个核心模型案例、现有 5 个研究样本和新增 1 个点名样本，共 9 个场景。
   在每个相关场景同时检查读取了哪些文档、计算前顺序、T 实际覆盖和输出内容。附加场景只在
   已观察失败或未覆盖的关键行为需要时增加。使用实际宿主许可，遇拒绝保留拒绝结果。
7. RQ-04 使用与 B0 相同的模型明确版本、参数、输入、工具与执行预算比较最终 B1；随机顺序、
   两个独立重复、版本盲评。事实错误先过硬门槛，再比较五维评分；不凭平均分掩盖越界或编造。
   质量目标：新版 ≥3.0/4、提升 ≥0.4，五维均值不下降，至少 6/9 场景改善且无单场景下降超过 0.25。
   Q08 证据充分仍只说观察时，决策维度最高 2 分且 AC-21 失败；Q09 评估新候选增量价值和策略能力边界。
   判据详见 spec 6.1；样本用于调参后必须如实改标回归样本，并另备正式验收输入。
8. 最后完成全量 pytest、实际变更 Python 的既有 Ruff、差异与范围审查。前后指标、受影响规则、
   各场景真实状态和未验证范围写入组件实施记录；不在本计划阶段宣称通过。

## 主要风险和取舍

| 风险 | 应对 |
|---|---|
| 缩短后模型遗漏安全或金融口径 | 按 INV 和原段落建立迁移表；关键入口保留短提醒；行为样本检查实际使用 |
| 条件估值文档未读就开始计算 | 明确触发前置条件，宿主回执比较加载与计算顺序；反例验收必须失败 |
| 文字预算让实现者机械删字 | 语义门禁优先；同时看字符和词数；不按行数/文件数考核 |
| 扩围研究仍被描述为完整技术覆盖 | 按实际 R/T、字段有效性核对，禁止由硬上限推断完成数量 |
| 测试依赖旧文档位置 | 改断言的定位与引用，保留不变量；不能把需验证的规则直接移除 |
| 合成评测不可执行或模型波动 | 分开记录 unavailable、失败和通过；原因明确后才重跑，不伪造当前通过 |
| 同工作区有未提交账户/交易修复 | 记录并排除其差异，单独验证自己的改动；不整仓回退 |
| 用长报告、引用数量或交易动作冒充质量 | 同证据和执行预算下评分；要求相关性与实质联系，不按篇幅加分 |
| 看过新旧标签产生评分偏好 | 随机标签、先评分后解盲，逐分定位报告与事实；生成者不自评宣布通过 |
| 模型/输入漂移或只挑最好一次 | 冻结配置并保留所有重复；条件不一致标不可比较，不缩小分母 |
| 为验收题调 prompt 或修改门槛 | 提前冻结，留出正式评测；已用于调参的题只作回归，不追认泛化改善 |
| 过度保守：有证据仍不给观点或取舍 | 正向机会案例设必要输出与扣分项；缺用户预算只限制个性化规模，不阻断方向判断 |
| 把进取误读为自动加杠杆或任意交易 | 分开观点确信度、方案条件和执行授权，主动建议本身不触发模拟/下单 |
| 新候选/策略无限扩围或稀释持仓分析 | 明确请求、2 候选/1 策略预算、共享 2 个估值名额；新增对象不混入账户表 |
| 使用真实报告回放造成私人数据进入仓库/评测 | 只记录通用需求，用独立合成输入复现问题，不复制用户账户或持仓组合 |

## 完成后的交付

- 更短的默认 prompt 与按需估值规则，所有现有维护细节可查。
- 规则归属/迁移表、默认与条件路径阅读量、完整测试及实际模型验收记录。
- 包含“扩围研究”和“点名但无技术结果”的可复验样本。
- 风险排序、关键传导、反证、顾问适配、主动组合方案、新候选/策略规则，以及 9 场景双版本盲评记录。
- 分别说明工程整理、行为不退化、研究提升是否通过；只在质量门槛满足时声称分析更好。
- 回滚步骤只覆盖本轮变更；不需要数据迁移、不改变产品版本、不自动发布。

单任务按 S/M 规模安排，共 18 个任务，文档切片通常 2–5 文件；PS-10/RQ-04 时长取决于模型和工具实际执行。
不对尚未执行的模型验收给固定耗时承诺。
