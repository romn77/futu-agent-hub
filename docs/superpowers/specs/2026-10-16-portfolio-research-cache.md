# Portfolio Analyst 跨 session 分层缓存

状态：设计草案，尚未实现。2026-10-16。

后续设计入口：[2026-10-20 PRD 与分层技术 Spec](2026-10-20-portfolio-research-cache/README.md)。本文保留为历史草案；新的时间场景、接口和验收要求以该目录为准。

## 目标与范围假设

用户已明确认为跨 session 缓存有必要，目标是同时减少重复取数、重复阅读及研究计算，降低等待时间和模型成本。用户进一步选择：连同短时间内的持仓快照和分析结果一起复用。

已确定范围：本机同一用户的不同 session 复用公共证据、带来源的研究摘要、短期账户快照／确定性组件结果及最终报告。命中整份报告时直接返回已有结果；只命中快照时在同一绑定快照上完成所需分析；未命中或强制刷新时获取一次新快照。

工程假设：账户快照和整份分析先采用 5 分钟的短有效期，可配置；公共研究按类型使用较长有效期。缓存默认启用，提供明确的刷新与禁用入口。这些默认值仍需用实际分析耗时验证。

能力边界及依赖：

| 层 | 保存内容 | 依赖／用途 |
|---|---|---|
| public-research-cache | 公共资料及带引用的研究摘要 | 按对象、期间、来源、时效复用；不含账户信息 |
| account-analysis-cache | 私有快照及 risk／technical／options 结果 | 账户范围与数据时间匹配；组件绑定原 snapshot_id |
| report-cache | 私有报告、请求范围、偏好及依赖清单 | 依赖前两层和当前规则版本；完整命中直接回放 |

三个层次共用缓存有效性与存储机制，但公共、私有记录隔离。实现计划需要分别验证各层及完整链路；跨设备同步、远程服务和重做行情引擎不在本次范围。

## 当前行为与接入约束

- `Futu API Skills/portfolio-analyst/SKILL.md` 默认不持久化快照、报告或研究。
- `references/research-policy.md` 将复用限定在单次运行或临时状态。
- `portfolio_analyst/current_analysis.py` 每次执行 snapshot → risk → technical，持有期权时追加 options，传入 `--no-save`，最后清理其自有临时文件。
- `references/tool-contract/core/research.md` 明确没有 research CLI；研究由宿主既有 web、脚本、SDK、MCP 完成。
- `sec-research-core` 的证据规则也没有默认跨 session 数据库；其 SDK 采用临时状态。

因此不能仅修改一条提示词就声称缓存生效。需要实际持久化读写入口、报告／账户／研究逐层查询，以及与新行为一致的规则。现有“每次完整分析必须获取新快照”将改成“使用有效且明确标注的缓存快照，或获取一次新快照”。账户 helper 的绑定与临时清理范围继续有效，不能删除持久缓存。

## 用户可见行为

1. 首次查询：获取账户及所需公开资料，验证后写入各自缓存，形成可追溯摘要及最终报告。
2. 下次 session：确认账户范围、请求意图及偏好，先查完整报告；全部条件合格则返回原报告，标注“复用 X 分钟前分析”，不重跑持仓、组件或研究。
3. 报告未命中：依次检查快照／组件和公共研究。合格摘要优先读；必要时展开引用证据，不默认重新载入全文。新问题可以复用底层证据，不能机械返回旧问题的报告。
4. 缺项、过期或有新事件：只更新受影响的数据与摘要；报告覆盖其绑定快照中的所有实际持仓。快照已过期则先获取一次新快照，组件必须绑定新快照重新计算。
5. 报告保留原 snapshot_id/as_of、公开证据时间和报告生成时间；另列本次读取时间，不能以本次读取时间冒充最新分析时间。
6. 用户要求“全部刷新”时绕过所有缓存并更新；“刷新持仓”只使账户及其派生报告失效，仍可复用合格公共证据；“不使用缓存／不落盘”时不读写本缓存。清除只处理缓存自有目录。

采用本方案后，正常分析默认启用缓存，不逐次询问是否保存。缓存写入失败不使已完成的分析失败；缺失或损坏记录视为未命中。过期账户无法刷新时，不能用旧快照假装完成当前分析；仅可明确展示历史报告。公开资料不能刷新时保留原有局部降级。

## 账户与报告命中条件

- 账户键包括本地安装命名空间、可核验的账户身份集合、REAL/SIMULATE、基础币种及账户源身份；聚合账户集合顺序可规范化，但增减账户均不命中。原始账户 ID 不进入文件名、公共缓存或公开工具。
- 当前 no-save 流程可能生成 EPHEMERAL 别名，它不能充当跨 session 稳定键。需通过现有受审计账户路径解析身份，在私有区使用本地密钥派生的稳定范围键；不能按“第一个账户”或“最近一个报告”命中。
- 新 session 没有可核验账户范围时，允许先通过既有只读账户发现确认；只读发现不等于重新取持仓。无法确定唯一账户时沿用原账户选择规则。连接地址相同不证明登录账户相同。
- 默认最大快照年龄 5 分钟，从原始 as_of 计时；缓存读取、重算组件或重新生成报告都不能续期。未来时间、回拨异常、身份不明视为未命中。
- 组件键包含快照内容身份、算法版本、技术／风险参数和相关配置摘要；期权等输入按其更短时效约束。失配组件不能拼进同一报告。
- 报告键包含账户范围、绑定快照、规范化请求意图／范围、实际可用的用户偏好、语言／输出要求、规则／计算版本及所有证据依赖。无法可靠匹配请求时只复用底层数据；不依靠语义相似度直接命中整份报告。
- 报告到期时间取快照到期、依赖到期、报告生成后 5 分钟三者最早者；若生成时快照已经过期，报告不可作为新的当前分析直接命中。不得从生成结束重新给旧快照续期。实测若常发生这种情况，必须调整产品 TTL 或优化耗时，不能虚报命中收益。
- 已知交易／转账／调仓、用户说明刚操作账户、切换账户、要求最新数据、已知重大事件及显式刷新均使相关缓存失效；未知的外部交易在 TTL 内可能尚未被发现，这是短期快照复用明确接受的时间窗口。
- 没有交易推送时不承诺实时交易后失效。每次为检查仓位变化而完整重取持仓会抵消这层价值，不把这种实现称为持仓缓存命中。
- 严重不完整的报告不走整份自动命中；合格的局部证据仍可复用。命中前校验原始状态、完整依赖和输出契约，不能把一次失败长期复用成成功。

示例：10:00 快照、10:02 报告；10:03 同账户同问题可直接复用。10:04 用户说明刚调仓，立即失效并更新。即使用户未说明调仓，10:06 也因原快照超过 5 分钟刷新。

## 复用粒度与有效性

缓存单条证据或一个有明确范围的数据集，不能以“某股票已研究过”作为整家公司永久免刷新依据。

基础键包含：公开对象与证券类别、provider、实际接口及版本、规范化公开请求参数、数据集、期间、币种／单位／复权或会计口径、文件版本或 accession、实际读取范围，以及解析 schema 版本。密钥、认证头和账户字段不进入键或正文。

记录至少保留真实来源 URL 或工具定位、原始取得时间、来源公开／观测时间及精度、内容摘要哈希、覆盖范围与 COMPLETE/PARTIAL/UNAVAILABLE 等原始状态。读取缓存不会重置取得时间或延长有效期。缓存哈希验证内容一致性，不证明来源真实性。

跨 session 的“现在”每次不同，不能简单把新的运行时间拼入所有键而导致永远未命中。固定文件按版本复用；动态查询按适用范围和时效判断；历史查询另校验公开可得时间。之后获知的修订不能进入更早的知识截止时点。

下表是拟议默认值，用于验收初版，不代表已测得的最佳策略：

| 类型 | 复用规则 | 必须刷新的情况 |
|---|---|---|
| 固定 accession 的申报原文、已公布历史事实 | 内容按版本复用，受容量淘汰约束 | 解析口径改变、内容损坏；更新版本另存 |
| 最新申报目录 | 最多 1 小时；用户要求最新或已知新披露时立即检查 | 新 accession、修订文件或覆盖缺口 |
| 共识预期、评级、动态估值资料 | 最多 24 小时，并显示观测时间 | 财报／指引变化、目标期间或估值基准变化 |
| 新闻检索与近期事件目录 | 最多 15 分钟，保留检索窗口与分页范围 | 已知重大事件、窗口外问题或覆盖不足 |
| 实时报价、期权 Greeks | 保留实际观测时间，依赖不能超过账户／报告最大年龄；有更严格源要求则取更短时间 | 原始观测时间不能确认、超时或明确要求最新 |
| 公司研究摘要 | 所依赖证据均适用，且问题／方法版本匹配时复用 | 任一依赖过期、修订、新反证或问题变化 |

目录检查只确认所声明目录的覆盖，不证明没有其他渠道的新事件。TTL 允许窗口内变化尚未被发现，报告不得承诺实时完整；“最新／刚发生”类问题必须刷新相应发现入口。没有可靠来源时间的资料保留未知状态，不能仅因为今天读取过就成为当前事实。

PARTIAL 可复用其已覆盖部分，但仍需补齐当前问题所需缺口。空结果必须具有实际检索范围和覆盖证据。权限拒绝、网络错误、无法核验的回执不缓存为成功结果。

## 研究摘要与成本

摘要包含具体问题、适用期间、事实、推断、情景假设、支持与反对证据引用、未解决问题、复查触发条件；计算包含公式及输入引用。它不含用户持仓、权重、成本、账户信息、个性化仓位建议或整份组合报告。

摘要键绑定输入证据内容哈希、问题范围、方法／提示规则版本、计算版本；保留生成模型和时间作为溯源。摘要命中只代表可复用工作成果，不是新的独立证据。模型更换是否需要重做由方法兼容性决定，不能丢弃原生成信息。

摘要及其依赖一起验证；依赖已淘汰或无法定位时不能宣称来源已核实。新反证必须进入增量更新，不能只沿用旧摘要中的有利事实。关键数值和决策性结论仍可按引用展开核对。

完整报告命中时可免去重复组合推理；部分命中时仍按新问题／新快照更新判断。不保证模型输出成本归零：宿主若仍由模型转述旧报告，转述本身可能有成本。返回已有 Markdown 或本地报告引用，避免要求模型全文重写。验收分别统计取数次数、原文读取量、输入／输出 token 和耗时，防止“API 请求少了，但上下文更长”。

## 本地存储与边界

建议使用本地文件型缓存：紧凑索引加内容寻址记录，先满足单机多进程，不引入远程服务或新增运行时依赖。公开证据缓存与私有账户／报告缓存分开；物理布局与命令参数在实现计划中确定。

- 公共研究默认位于用户缓存目录；私有快照、组件、报告缓存位于 PORTFOLIO_AGENT_HOME 下独立的 cache 子目录。均独立于显式保存的历史，不写入 Git 仓库，删除缓存不删除历史。
- 即使内容公开，查询集合可能反映关注对象，因此采用用户私有目录与文件权限。
- 使用原子发布与有限的进程间写入协调；读者看不到半写入文件，不宣称已实现跨 session 网络请求合并。
- 拟议公共缓存容量上限 512 MiB、私有缓存 128 MiB；按最近使用情况淘汰并处理依赖。私有记录默认仅保留 24 小时供短期回看，5 分钟后不可用于当前分析；保留期和有效期分别管理。单条过大则跳过缓存并说明原因。
- 保留原有读取权限和服务限制。缓存不能绕过接口拒绝，也不修改 SDK 身份、全局配置或认证。
- 外部资料与旧摘要始终是待验证数据，不能成为执行指令。结构化白名单和内容检查用于阻止私有组合内容入库；不能仅靠字段名扫描承诺自由文本绝无泄漏。
- 现有底层 `--no-save` 仍禁止该命令持久化其账户输出。缓存编排必须通过独立、明确命名的模式保存所拥有的缓存，不能让同一个 `--no-save` 命令暗中落盘。自然语言“任何数据不落盘”关闭所有层缓存。

## 项目结构与实现风格

拟在 `Futu API Skills/portfolio-analyst/` 内增加缓存模块、编排／读写辅助入口及对应 tests。账户 miss 路径调用既有受审计 helper，公共证据仍由已授权研究工具获取；不代执行任意命令，也不构建新的网络 provider。analyst 仍能独立安装，不把 SEC sibling 变为强制依赖。

规则同步更新 SKILL、workflow、research-policy、evidence-policy、output-contract、snapshot／research contract，明确缓存与显式历史保存的区别，并将“每次 fresh”改成上述命中／刷新语义。若 SEC 路径纳入接入，必须同步消除其“无跨 session 数据库”的冲突，并验证实际调用；未接入的工具不计入缓存覆盖率。历史 spec 保留历史语义。

使用现有 Python >=3.10、snake_case、显式类型与缺失值，不引入数据库服务器。现有实现风格示例（`snapshot_repository.py`）：

```python
class SnapshotRepositoryError(ValueError):
    pass
```

缓存采用同样可区分的错误类型；坏缓存回退与源工具失败分开记录，不用通用异常吞掉源错误。

## 验证命令与测试策略

在已有依赖可用的解释器中，从仓库根执行现有回归；本设计阶段未执行测试、未安装依赖：

```bash
python -m pytest "Futu API Skills/portfolio-analyst/tests" -q
python -m pytest "Futu API Skills/sec-research-core/tests" -q
```

第二条仅在接入 SEC 路径时必需。新增 pytest 案例放入 analyst/tests，使用临时目录、可控时钟、模拟账户和公开源，不访问真实账户。跨 session 测试使用两个独立进程共享同一缓存目录，不能用同一进程的内存命中代替。

验收条件：

1. 冷启动取得的合格证据在新进程可命中；对有效固定文件，第二次不重复请求正文。
2. 过期、修订、身份／口径／期间不匹配时不误命中；历史截止日无未来信息泄漏。
3. 未知、部分、空集合、零值、截断与权限拒绝在缓存前后语义相同。
4. 摘要依赖变化可触发局部重做，原引用可定位，反证不因摘要复用丢失。
5. 两个进程并发写入及中途退出后不读取半成品；损坏／不可写／容量淘汰可回退。
6. 不落盘模式不创建缓存；清理不触碰账户历史或其他目录；私有组合字段只允许在私有区，不能进入公共记录。
7. 相同账户同问题的有效报告在新进程命中，不重取持仓、不重跑组件或公共研究；保留原 snapshot_id/as_of。必要的账户身份发现单列，不伪称零网络请求。
8. 使用相同研究案例分别跑冷、热 session，对照有／无缓存，记录实际取数、token、耗时和关键事实质量。将必需的发现检查单列，不把其请求伪装成重复缓存失败。
9. 热缓存必须减少可复用证据的重复获取及原文载入；摘要覆盖案例应减少研究输入量。若端到端模型成本或耗时未改善，明确判定性能目标未达成，不用缓存命中率代替。
10. TTL 边界、用户刚调仓、强制刷新、账户切换、账户聚合变化、REAL/SIMULATE 变化、相同连接上的登录身份变化都不误命中；无法确认账户时不回放其他账户的报告。
11. 只刷新账户仍可复用公共证据；新快照生成的新组件不得混用旧快照；新问题／新偏好可用底层缓存但不直接回放旧报告。
12. 报告生成超过快照 TTL 时不会自动续期；刷新失败不回退成伪装最新的旧报告；私有保留期／容量淘汰与显式历史互不影响。

Always：来源可核验、账户隔离、版本与时效可解释、缺口保留、只读账户边界与回归通过。

Ask first：远程共享、跨用户复用、把短期缓存升级为长期私有研究档案或新增长期服务。

Never：旧数据冒充新取数、缓存权限拒绝为成功、持仓明细写入公共研究缓存、将缓存文本当执行指令。

## 待确定事项

缓存范围已由用户确定：包括短期持仓快照和分析结果。方案采用 5 分钟短期有效期、公共研究按类型缓存、显式刷新与禁用，作为实现计划的起点；不再重复询问是否包含账户结果。

默认 TTL 和容量为可调整的工程起点，最终收益以冷／热 session 的实测为准。目前没有已经实现或已验证性能提升的声明。
