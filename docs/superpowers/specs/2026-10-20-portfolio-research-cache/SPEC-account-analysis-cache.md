# 账户分析缓存 Spec

模块：`account-analysis-cache`。状态：待评审，未实现。依赖 `cache-core`；行情复用公共研究模块。覆盖产品需求 R01、R04、R06、R07、R08、R09、R10、R11、R12、R14。

## 1 目标

让短时间重复组合分析复用同一账户范围的合格快照和计算结果。未命中时继续调用现有受审计只读获取路径；最终报告中的所有账户计算严格绑定同一 snapshot_id/as_of。

默认业务仍是 REAL/USD；不得通过缓存新增原命令不支持的市场或账户聚合。键保留环境和币种，防止未来或已有其他受支持入口误用。

## 2 先确认账户，再查缓存

`AccountScope` 包含：安装命名空间、经核验的账户集合、交易环境、基础币种、券商/账户源身份及可得的登录会话身份。账户集合规范化排序，增减成员均形成不同范围。原始账户 ID 仅在受控内存或现有私有配置内处理；缓存使用本地稳定密钥派生的 HMAC 范围键。

不得使用 EPHEMERAL 别名、默认第一账户、最近报告、端口或 host 地址替代账户身份。沿用现有“唯一合格账户才可自动选择，多账户需明确选择”的规则，不因命中候选而绕过选择。

新 session 若没有可信账户范围，先通过既有受审计逻辑做只读账户发现。需要将发现/选择逻辑与完整持仓获取分开复用；不能为判断能否命中而先完整拉取持仓。可信宿主会话绑定只有在可验证账户切换状态时才可替代新发现，缺少此能力就执行只读发现。

缓存中保存的快照可以保留其原始别名和 snapshot_id；独立的稳定范围键证明归属，不能为适配新 session 随意重写快照中的别名。建立新的密钥或范围元数据属于明确启用的缓存编排行为，不能隐藏在旧 `--no-save` 命令中。`cache_mode=off` 不创建缓存身份密钥。

## 3 快照命中与刷新

命中要求：范围、来源/规范化版本、配置相容；快照结构、业务语义与完整选定账户覆盖验证通过；原 as_of 未满 300 秒；没有已知交易/资金变化或当前账户 generation 失效。使用 `<` 判定有效，恰好 300 秒即过期。

账户索引指向当前合格快照，并保留受控的失效 generation。新的成功快照成为当前指针；显式刷新、已知交易或资金变化使旧当前报告失效，即使旧文件尚在保留期。失败刷新不能恢复原来已被事件失效的当前状态。

默认 miss 只获取一次账户快照。需要新计算结果时沿用 risk → technical → 持有期权时 options 的顺序；风险不可用时保持已有局部降级和技术选择规则。账户 fatal、绑定错误、无法安全清理等原有错误不得改成缓存成功。

miss 路径保留 OpenD 资金 NAV 作为权威值。公开报价更新不能重标记旧资金 NAV 的 as_of。当前报告不得将 S1 的现金/NAV、S2 的仓位和旧期权结果拼在一起。

可缓存的快照仍需保留 `COMPLETE/PARTIAL` 等原质量状态。账户选择或选定账户读取不完整时不成为当前完整快照命中；其他已允许的局部缺口依原契约处理，不为命中删除缺项。

## 4 计算结果键

`AnalysisArtifact` 必须包含：

- 原 snapshot_id、原 as_of、规范化快照内容 hash 与稳定账户范围键。
- 结果种类（risk、technical、options）、schema/算法版本与实际加载代码摘要。
- lookback、选择条件、政策配置、证券分类/元数据、FX 等实际影响计算的输入摘要。
- 行情、报价、合约元数据等源证据引用与有效性；没有使用的输入不伪造依赖。
- 原完整性、降级和预算状态。

同一快照与兼容输入可复用已验证结果；新快照形成新的结果键。风险与技术可以共享原始行情，但不能直接把旧报告换个 snapshot_id。期权的时变结果须匹配报价有效期与当前分析时点；默认不使用超过账户上限或来源更严格期限的报价，来源时间未知时不作为当前可回放结果。

缓存命中仍执行有界的结构、摘要、依赖与必要语义验证。现有技术/期权报告的纯本地重放校验不计为重新获取源数据，也不能为了减少“分析函数调用次数”而关闭。将其耗时单独记录，性能优化不能减少正确性验证。

现有 helper 清理的 `OwnedTemporaryRun` 仅管理本次临时文件。缓存命中若需要向原 CLI 提供快照文件，应复制到本次受控临时目录；清理不能接管持久缓存路径。生产接口可以逐步改成内存输入，但不得绕过既有验证。

## 5 当前、日终和历史

- `current`：满足原始快照和相关报价有效期，默认 300 秒；用户要求 latest 时重新读取。
- `historical`：指定 snapshot_id 或可明确解析的历史时点，保留当时的账户事实。不会把历史报告宣传为当前建议。
- 日终复盘是 historical 的明确场景。必须已有该交易日和时间范围的合格快照；没有历史记录时不能用今天的数据倒推当日持仓。
- 当前快照不因“当天已经分析过”而获得一整天有效期。日终记录也不能代替盘中最新资产。

历史查询首先使用用户明确指定的现有记录；短期缓存尚保留的旧快照可以临时回看，但不能承诺昨天一定仍存在。长期对比继续依赖用户明确保存的 SnapshotRepository 历史；本功能不自动扫描或创建长期账户档案。

## 6 失效事件与控制

| 场景 | 行为 |
|---|---|
| 用户说明刚交易/转账/调仓 | 提升账户 generation，刷新账户与派生结果；公共资料按自身状态保留 |
| 新 session 或登录身份不明 | 先发现并确认账户；不能只按旧范围键回放 |
| 聚合账户增减、REAL/SIMULATE 或币种变化 | 新范围，原报告 miss；不自动合并跨账户快照 |
| `refresh_account` | 强制新快照及相关计算；合格公共证据正常复用 |
| `refresh_all` | 同时按总策略刷新所需公开证据与研究 |
| `off` | 不读取或持久化本缓存，保留原执行路径 |
| 刷新失败 | 保留错误；可展示明确历史结果，不返回伪装最新的当前报告 |

没有交易推送时只对已知事件提前失效；未告知的外部变化可能在 TTL 内尚未被发现。只读发现不能被错误计为持仓刷新，也不能被省略后宣称账户身份已确认。

## 7 新入口与兼容性

计划增加顶层组合入口 `scripts/cached_analysis.py`，由报告编排在原 helper 之前完成请求匹配与报告查询，再调用本模块判定账户缓存。本模块不导入报告模块，避免逆向依赖。输入使用版本化 `AnalysisRequest`：缓存模式、分析模式、问题/范围、偏好摘要、语言、方法版本、请求截止及明确账户选择。原始私有账户选择不进入普通诊断和公开记录。

顶层入口输出是两种互斥路由；本模块只负责第二种路由中的账户和计算结果：

- `report_hit`：已验证报告引用、原始数据时间和回放内容；宿主终止全量研究路径。
- `components_ready`：一个绑定快照及 risk/technical/options 结果、局部降级、缓存使用证据和待研究范围；宿主继续必要研究。

现有 `scripts/current_analysis.py` 保持显式无缓存入口。新编排提取/复用其受审计获取与绑定能力，并将缓存策略放在外层；不得以直接读取未经审计 SDK 取代原来源。需要复用同一快照重算组件时，应复用原逻辑而不是再次获取账户。

拟议命令，实施后从 analyst Skill 目录执行：

```bash
python scripts/cached_analysis.py --request /absolute/private/run/analysis-request.json --json
```

如果基础缓存或可选来源后端不可用，明确走原流程；源读取拒绝或账户不明仍遵守原错误规则，不借降级扩展权限。

## 8 长分析跨越有效期

最终输出前重新检查快照和动态依赖。若研究耗时使账户过期，保留仍合格的公共研究；当前用途允许最多一次补充账户刷新，并将所有账户计算及报告相关段落重新绑定到新快照。这里改变的是新编排的契约，需同步旧“每次一次 fresh”的 Skill 规则；每份最终报告仍只有一个账户快照。

补刷新后的结果若仍在输出前过期，停止自动刷新循环，明确返回带历史时点的结果或当前分析无法完成的状态；不能不断延长 TTL，也不能把已完成的公司研究全部丢弃重来。记录补刷新次数和原因。

## 9 实现位置与验证

涉及 `current_analysis.py`、`service.py`、账户发现/选择逻辑、Settings、account_alias、各组件来源创建位置与新缓存包。保持旧 snapshot/report schema 和显式历史持久化语义；缓存外层 metadata 使用新 schema。

结构、代码风格、通用命令和范围控制按[总 Spec](SPEC.md)。拟议定向测试，实施后从 analyst Skill 目录执行：

```bash
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m pytest tests/test_cache_account.py tests/test_cache_processes.py tests/test_current_analysis_helper.py -q -p no:cacheprovider
```

重点验收：新进程先发现身份再命中；有效快照不重取持仓；随机别名不误作范围键；账户/聚合/环境切换 miss；精确 TTL 边界；已知事件提前失效；组件输入变化；同一快照绑定；报价更短期限；不可写与关闭缓存；一次补刷新上限。最终回归包含原账户选择、数值、报告语义和临时清理测试。
