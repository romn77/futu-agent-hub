# 组合分析与研究缓存 PRD

版本：0.1。日期：2026-10-20。状态：待评审，未实现。技术设计和文档状态见[设计索引](README.md)。

## 问题陈述

用户重复分析同一组合或公司时，系统往往再次获取账户快照、拉取历史行情、读取 SEC 文件、组织研究并生成整份报告。即使只有价格或少量仓位变化，之前完成的研究也难以自动复用。等待时间和模型成本随分析次数重复发生，已保存的文件没有成为可靠的复用入口。

现有实现主要支持同次运行内的证据共享；默认 helper 每次取新快照，执行风险和技术分析，持有期权时追加期权分析，随后清理临时结果。离线排查已验证重复命令路径，但尚无真实端到端成本基准。

## 解决方案

在所有相关分析前增加缓存判定。先确认账户、问题和时间范围，再检查完整报告及其依赖。完整命中时回放原报告；部分命中时复用已有证据、研究摘要和适用计算结果，仅获取缺项或更新发生变化的部分。

公开证据、私人账户结果和最终报告分别管理。SEC 原文以申报版本为基准，最新申报目录以短期检查为基准；账户以实际快照时间为基准；研究结果以问题、方法和证据依赖为基准。缓存读取不能改变原始数据时间。

## 用户故事

1. 作为重复查看组合的用户，我希望短时间内问同一问题时直接得到已有结果，从而避免等待完整分析。
2. 作为跨 thread 工作的用户，我希望新 thread 能找到合格研究，从而无需重复下载和阅读相同文件。
3. 作为公司研究用户，我希望同一 SEC 申报原文按版本复用，从而将时间用于分析变化。
4. 作为关注新财报的用户，我希望新申报或修订触发相关研究更新，从而不会沿用过时结论。
5. 作为机构研究用户，我希望只补采新申报和缺失期间，从而避免重新采集整个机构池。
6. 作为组合用户，我希望风险和技术分析共享口径一致的行情，从而减少重叠取数。
7. 作为研究用户，我希望复用带引用的研究摘要，从而减少模型重复阅读全文。
8. 作为改变研究问题的用户，我希望复用证据但获得针对新问题的回答，从而不会收到机械重复的旧报告。
9. 作为盘中用户，我希望账户、资产估值和期权报价有明确的有效期，从而知道报告反映哪个时点。
10. 作为刚调仓的用户，我希望告知操作后立即刷新账户相关结果，从而无需等待 TTL 到期。
11. 作为多账户用户，我希望缓存严格匹配实际账户范围，从而不混用另一账户或聚合组合的数据。
12. 作为复盘用户，我希望按明确时点查看已有历史快照，从而把历史分析与当前分析区分开。
13. 作为用户，我希望“刷新持仓”保留仍有效的公共研究，从而减少无关重复工作。
14. 作为用户，我希望“全部刷新”绕过本次缓存命中，从而重新取得所需资料。
15. 作为重视本地数据控制的用户，我希望能禁用缓存和清理缓存，从而控制持久化范围。
16. 作为用户，我希望报告显示原快照和研究时间，从而不会把旧数据误认成刚取到的数据。
17. 作为用户，我希望缓存损坏或不可写时仍能执行正常分析，从而不会因为加速功能失去原能力。
18. 作为用户，我希望数据源失败时明确展示缺口，从而不会把过期缓存误当成刷新成功。
19. 作为并行运行多个 thread 的用户，我希望它们协调相同取数任务，从而减少同时重复请求。
20. 作为维护者，我希望看到分层命中、失效原因、源调用、token 和耗时，从而验证优化是否有效。
21. 作为已有 Skill 的用户，我希望安装方式、研究范围和原有显式存档仍可使用，从而无需迁移历史记录。
22. 作为用户，我希望缓存不会自动启动定时任务或共享到远端，从而使本次功能范围保持明确。

## 产品需求

| ID | 要求 | 首版完成条件 |
|---|---|---|
| R01 | 跨 session 复用 | 两个独立进程可命中同一有效条目；不依赖聊天上下文或单进程内存 |
| R02 | 公共证据按版本与范围复用 | SEC 正文、发现目录及合格历史行情分开管理；只补缺项和变化 |
| R03 | 研究摘要复用 | 摘要保留问题、引用、反证、缺口和方法版本；有效时减少原文重读 |
| R04 | 短期账户和计算结果复用 | 先核验账户范围；命中保留原 snapshot_id/as_of；变化后重绑计算 |
| R05 | 完整报告回放 | 同账户、同请求、同偏好、版本兼容且依赖全部有效时直接返回已有报告 |
| R06 | 明确刷新与提前失效 | 支持正常复用、只刷新账户、全部刷新、缓存关闭；已知事件提前失效 |
| R07 | 当前与历史语义分开 | 当前分析按短期有效性判断；历史复盘绑定明确时点；短期缓存不承诺永久档案 |
| R08 | 时间与来源可解释 | 原始数据时间、取得时间、报告时间和本次读取时间不混淆；不自动续期 |
| R09 | 本地账户隔离 | 公开证据不含私人组合数据；账户和报告位于用户私有区；不同账户不误命中 |
| R10 | 完整性与结论质量 | PARTIAL、空结果、截断、未知值与拒绝保留原语义；不把缓存当独立事实证据 |
| R11 | 多进程正确性 | 无半文件、过期持有者发布或跨进程错配；相同受控请求具备在途协调 |
| R12 | 故障可恢复 | 缓存问题可回退，源数据失败按既有规则处理；不冒充最新结果 |
| R13 | 可验证的成本收益 | 记录外部取数、正文载入、确定性计算、模型 token 和耗时；以冷/热对照验收 |
| R14 | 渐进接入与兼容 | 原命令和显式历史保存语义不变；未接入来源单列；Skill 与实现同步 |
| R15 | 控制运行范围 | 默认按请求检查，无后台任务、远程同步、新增交易动作或额外研究范围 |

## 时间规则和用户可见行为

下面是初始工程参数，不是实时性保证。更严格的来源要求或用户明确要求最新时，采用更严格规则。

| 内容 | 当前用途的默认有效性 | 提前失效条件 |
|---|---|---|
| 账户快照 | 原始 as_of 后最多 5 分钟 | 已知交易/资金变动、账户范围变化、要求最新 |
| 资产净值与行情 | 按各自来源时间，不能以全天旧值回答盘中当前值 | 来源过期、价格或资金更新；净资产仍取 OpenD 资金数据 |
| 已完成的历史 K 线 | 对应交易周期、覆盖范围与复权版本仍适用 | 新交易周期、公司行动、数据修订；未完成周线单独更新 |
| 固定 SEC 原文 | 指定申报和内容版本可持续复用，受存储淘汰限制 | 修订产生新版本、内容损坏或解析版本不兼容 |
| SEC 最新目录 | 检查后最多 1 小时 | 已知新申报、要求最新、覆盖不足 |
| 新闻发现 | 最多 15 分钟 | 已知重大事件、检索范围变化、要求最新 |
| 共识、评级和动态估值资料 | 最多 24 小时，来源允许时；不含实时报价/Greeks | 财报/指引变化、预测期间变化、要求最新 |
| 研究摘要 | 依赖、问题和方法均有效 | 任一相关证据发生变化或需要的新证据缺失 |
| 最终组合报告 | 不晚于原快照、任一依赖或报告生成后 5 分钟的最早期限 | 请求、偏好、账户或方法变化 |

日终复盘使用明确交易日和当时快照。查询“现在”不会因为当天已有一份日终基线而跳过时效判断。行情价格更新不会自动把旧账户 NAV 标成最新。

缓存过期不自动启动工作；下次请求到来时检查。过期条目尚在保留期内可以用于明确历史用途。公共区容量初始 512 MiB，私有区 128 MiB；私人缓存最多保留 24 小时，可因容量提前淘汰。长期历史保存继续使用独立的显式归档能力。

## 核心场景

起点：10:00 获取账户快照，10:02 完成报告；账户 10:05 到期，SEC 目录 11:00 到期。其他未提及证据均假定有效。各场景相互独立。

1. 10:03 同问题：命中报告，返回原数据时间，不重新组织整轮研究。
2. 10:06 当前组合：刷新账户并更新相关计算，复用合格财报与研究摘要。
3. 10:04 告知调仓：立即失效账户相关结果；无需等待 10:05。
4. 10:04 已知 SEC 新申报：检查目录、补取新文档、更新相关研究；其他公司研究可复用。
5. 次日再分析：刷新账户和已过期发现入口，固定文档未变化时继续复用。
6. 10:03 换研究问题：旧报告不直接命中，但证据和适用摘要可复用。
7. 10:06 才完成首次报告：旧快照不能续期；保留公共研究，更新当前账户相关部分，或明确作为历史报告输出。

没有交易事件推送且用户未告知时，短期窗口内可能尚未发现调仓；没有主动新披露检查时，目录窗口内可能尚未发现 SEC 新申报。产品不得宣称即时感知所有变化。

## 实现决策

- 四个模块为共享缓存核心、公共研究缓存、账户分析缓存和报告缓存；缓存策略在统一入口执行。
- 本机文件型缓存与内容摘要标识，不引入数据库服务器、后台服务或新的网络数据平台。
- 账户缓存与公共证据隔离；通过本地稳定身份核验账户范围，不能使用随机临时别名或连接地址替代。
- 保留现有受审计取数与数值验证能力；已完成的计算或报告只有在依赖兼容时复用。
- 宿主必须先查研究摘要和证据，再调用原有授权工具；工具内部缓存不算最终报告复用。
- 同键并发使用有期限的任务所有权与发布校验。中断恢复不承诺外部网络请求严格只执行一次。
- 配置允许调整有效期和容量，但增大有效期不能作为修复性能问题的默认手段。

## 测试决策与效果要求

测试覆盖四个模块的公开行为及其连接，不以检查内部字典或函数调用实现细节替代业务结果。使用合成账户、可控时钟、固定公开样例、可计数的源替身，以及两个独立进程共享临时缓存目录。

沿用已有账户选择、快照绑定、报告重放验证和 SEC 期间/版本测试。新增时间边界、更新传播、损坏、并发、禁止持久化、跨进程命中与完整工作流评测。

确定性验收要求：有效完整报告的热运行不重新取得持仓、不执行分析引擎和公共研究；有效固定文档不重复读取正文；新快照只影响相关计算。必要的身份发现和目录检查单独计数。

性能验收使用至少三个代表性案例，每例至少五组可比的冷/热运行。公共摘要场景应减少源正文载入和模型输入；完整报告场景应避免重新生成全文；热运行耗时中位数应下降。记录绝对值与变化量，不预先宣称固定提速比例。拿不到真实 token 时标记 unavailable，不用字符数冒充；对应成本结论保持未验收。

## 不在范围内

- 后台定时刷新、交易推送接入、邮件或聊天通知。
- 多设备同步、远程或跨用户缓存、长期私人研究档案的自动建立。
- 新建行情/SEC 爬虫、替换现有数据源、放宽账户读取权限或新增交易能力。
- 用模糊语义相似度直接返回旧报告，或用旧报价替代要求最新的数据。
- 将原有持仓研究数量、估值预算或可选工作流因缓存命中而自动扩大。
