# 分层缓存验收规范

日期：2026-10-20。状态：待执行的验收要求；以下不是已通过的测试报告。需求编号来自 [PRD](PRD.md)，契约以[总 Spec](SPEC.md)及三个分层 Spec 为准。

## 1 验证方式

核心/业务测试使用合成账户和可控源，不连接真实资金账户。所有跨 session 条件至少由两个独立进程、同一受控缓存目录验证。宿主工作流另用实际工具回执验证，不能用模型自述“命中”替代。真实公开源和账户性能测试须在既有授权范围内执行，不作为单元测试前置条件。

测试钟支持推进、恰好到期和回拨。源替身分别统计身份发现、持仓读取、目录检查、固定正文读取、行情、分析引擎、摘要与报告生成。客户端本地语义重放单列。

## 3 七个时间场景

共同起点：账户 S1 于 10:00 取得，10:05 到期；SEC 目录于 10:00 完整检查，11:00 到期；已有固定文档 F1 及对应摘要；报告 R1 于 10:02 完成。各场景独立，其余依赖假定合格。

| 场景 | 时间/变化 | 必须观察到的结果 | 验收项 |
|---|---|---|---|
| 同问题重看 | 10:03 | 回放 R1，显示账户时间 10:00；无重复持仓、引擎或研究 | RP01、RP07 |
| 快照过期 | 10:06 | 取得 S2，重绑账户计算；F1 和适用摘要命中 | A03、A05、X01 |
| 已知调仓 | 10:04 | 提前失效 S1 当前用途；公共材料不因调仓全部清空 | A04 |
| 新 SEC 财报 | 10:04 | 提前查目录、补取 F2、更新受影响论点；其他材料可复用 | P03、P11 |
| 次日分析 | 下一日 | 更新账户与到期发现入口；目录未变时保留 F1 和合格摘要 | P02、A03 |
| 新问题 | 10:03 | 完整报告 miss，已有证据和适用摘要继续可用 | RP03、P10 |
| 生成太慢 | 首份报告 10:06 才完成 | 原 S1 不能续期；保留研究，最多一次补刷新；仍失败则明确历史/不可用 | RP02、RP05 |

另验证尚未到 TTL 且无推送/用户事件时，系统不宣称已发现外部交易或新申报；这属于允许的 bounded freshness 窗口。TTL 到期本身不启动任务，首次后续请求才发生更新。

## 4 冷热运行指标

至少三个案例：仅股票组合、含期权组合、公司/机构 SEC 研究。每例至少五组冷/热配对运行；记录输入、配置/代码版本、受控时间、来源实际覆盖及宿主。缓存目录重置只操作本案例的临时自有目录。

每轮必须记录：

1. 本地 lookup/命中/失效原因及所命中层。
2. 身份发现、账户持仓读取、目录检查、正文/行情获取各自次数；HTTP 可见时另计实际 HTTP，不能混用方法数。
3. 取回字节与实际送入模型的正文/摘要量。
4. 分析引擎执行次数与验证重放耗时。
5. 宿主可得的真实输入/输出 token；不可得为 null 并说明。
6. 阶段和总耗时、额外补刷新次数、最终覆盖与关键事实一致性。

功能通过标准：热报告命中跳过其依赖已经完成的取数/引擎/整轮生成；热固定证据查询不重复正文获取；新增证据只影响实际依赖。必要发现检查不算失败，但必须计入总成本。

性能通过标准：摘要路线减少全文输入和可得的真实模型输入 token；报告路线避免重新生成全文；可比热运行总耗时中位数低于冷运行。所有关键事实、反证、缺口与快照绑定保持。若缺少 token 计量，模型成本部分标为未验收；若命中率高但端到端不改善，不能宣布性能目标完成。

现有完整回归命令见[总 Spec](SPEC.md)。实施后新增测试文件分别对应 core/processes、public/summaries、account、report/host_flow；本阶段这些文件尚未创建。真实源基准单独执行，不混入离线 pytest。

交付记录至少包含：实现版本、安装验证、已接入/未接入来源、每个验收项 PASS/FAIL/NOT_RUN 与证据、冷/热指标、已知限制。跨进程用两个真实进程；宿主接入用实际工具调用回执；不能用单次函数调用或自述代替。

排查阶段 35 项原有测试通过及合成调用计数是现状证据，不能填写为本验收表的通过结果。此目录的当前完成项仅为文档结构、需求覆盖、链接与规则一致性核对。
