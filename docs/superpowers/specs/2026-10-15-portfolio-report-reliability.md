## R-01 Complete account fields

当前评测只数持仓代码，错误数值或遗漏盈亏仍可能通过。增加评测专属的独立 Markdown
核对，绑定同一 snapshot，检查每个非零证券的权重、市值和未实现盈亏；按列头识别，
允许中英文、列次序、合理显示舍入、美元标记和明确的单位缩放。
空值、文字错列、符号错误、未知填零、错误 NAV 权重、缺/重复行必须不能通过。
不同账户同一证券按 canonical identity 汇总时，缺失值保持未知，不把部分合计当完整。
未知语法或无法核验的单位标记为不可验证，不猜测或自动修正模型报告。
保留旧 execution/assertion 门槛并增加字段检查；不以新增检查的失败重写旧回执。

生产指令在原 output/evidence 归属中补充简短的最后核对：从保留的 snapshot 核对
最终表格的字段与对齐；现金余额是时点存量，CFO/CapEx/FCF 是期间流量。
不得从 CFO−CapEx 推导余额，不得用期末余额解释现金产生能力；有直接余额时引用原字段。
不增加新的生产校验服务、默认文件或公开报告中的检查日志。

## R-02 Research allocation and falsification

保留 8 个深研、2 个估值和实际 technical 结果边界。已核实的简单储备基金按原规则
在概览处理，空出的研究精力用于重要公司问题；基金性质不明、被点名或有实质风险时
正常计入研究预算。不能只因大额储备而宣称完成了较高比例的公司研究。
共有需求风险与其财报触发窗口合并解释；小额复杂工具按实际金额/敏感度和用途比较，
不能凭工具名称排序。实质反证应改变判断或得到具体回应，不能只追加泛泛风险语句。
仅在真实评测发现缺口时细改原规则，不以关键词堆积作为实现。

## R-03 Observable reference reuse

从 host 的成功 command_execution 回执统计完整读取的文档、重复次数和重复输出字符。
同一 item ID 的重复日志只计一次；失败/截断输出不算完整读取。分段读取可记录为
未核实，不伪称已经完整覆盖。统计 turn.completed 的实际 usage，缺字段保持未知。
完整读取成本和模型 token 用量分别报告，不把文档字数下降当成费用或延迟下降。
重复读取是诊断证据；说明是否因版本改变或内容缺失，不以“越少读取越好”弱化必读要求。

## R-04 New frozen comparison

先冻结当前 R0 指令及运行代码，再冻结三项独立设计的新合成留出输入与操作者量表。
至少包含：24–40 持仓和大额储备基金；期间/单位/现金流与余额区别；明确主动调整请求
及埋在正常披露中的反证。模型输入只含用户请求、原始证据、必要接口说明，不含评分目标、
期望答案、旧报告或版本标签。继续使用现有 public_reader 和合成账户路径。

新留出集每案 R0/R1 各两次，共 12 份报告；旧 Q02/Q05 各两次 R1 作为四份缺陷回归，
不计入泛化比较。双方使用相同 runtime、输入、公共工具、方法、配置、600 秒/8 MiB
执行预算和随机预登记顺序。只有产品指令可不同。每次新进程，不共享报告。
临时服务失败仅按原因另建尝试；保留原件，不挑选好结果或无限重试。

冻结请求模型为原 spec 使用的 `gpt-6-astra`、reasoning `medium`；记录实际 CLI 路径、
版本与启动文件哈希。服务端 revision 若不可见，明确比较仅为同请求配置、非严格同权重
受控试验，不宣称统计显著或普遍改善。实际执行仍服从宿主审批，不绕过拒绝。

本轮验收层次：

1. 工程：新负例真实 RED→GREEN，全量回归通过，生产引擎/schema 不变，D0 原预算不变。
2. 缺陷回归：最终 R1 的四份报告不漏/错关键账户字段、不混淆现金存量与期间流量；
   两项问题均需真实报告与回执确认。自动检查不覆盖的语义由独立审查判断。
3. 留出可靠性：R1 六份报告无关键事实/交易/隐私错误；每份 F、R、C 均至少 3/4；
   所有账户字段检查通过，三个案例的新旧五维均分不下降超过 0.25，事实维度总体不下降。
   任一缺执行/缺审查保持未完成，不能缩小分母。每次结果和重复跨度全部报告。
4. 改善主张：仅当新留出集均分严格提高、至少 2/3 案例改善且各维度均值不下降时，
   才能说本轮样本改善；否则仅报告可靠性/工程结果。永远不能据此改写历史 AC-17。
5. 复用：报告首次完整读取后的重复次数、原始输出量和实际 usage；目标是无无理由完整
   重读，若仍有重读则保留该项未通过。不能靠测试专用禁止重读提示使 R1 独获帮助。

操作者评分锁定后解盲；独立代理不得知道版本或原评分。代理评审不等同独立人类验证。
看到留出结果后不再调该版本；发现问题列为下一轮回归并另建留出输入。
