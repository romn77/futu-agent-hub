## 1. 目标与前提

用户需要知道什么最影响组合、哪里存在机会、当前应优先考虑哪些取舍，以及什么会改变判断。
维护者需要规则明确且易于修改；模型需要先读必要规则，再按条件加载估值细则和其他专题。

目标分成两个独立的验收维度：工程整理必须不退化；研究质量必须在相同证据条件下得到
可观察的提升。通过词数、结构或回归检查不能单独声称研究质量提高。

本版采用以下设计前提：

- 默认深度研究最多 8 个标的、自动完整估值最多 2 个；用户明确要求可扩大相应范围。
- 技术分析仍使用当前引擎与最多 8 个标的的硬上限，不新增 helper 参数、不改技术选择算法。
  深研的 prompt 选择与精力分配按 FR-13 改进，与 technical 的实际覆盖分别说明。
- “精简”不允许删除财务口径、来源核验、隐私、只读或失败处理要求。
- 提升研究质量主要发生在现有 portfolio/research/output/recommendation 指令中，不改变
  风险计算引擎。明确进取型顾问请求时，按 FR-17 有限增加公共研究，不以篇幅或交易次数作为质量指标。
- 本用户已明确希望三种输出同时出现：鲜明观点、持仓调整建议、新标的/事件/进攻策略。
  这是本次需求范围，不推导出其可承受任意回撤、愿意加杠杆或已授权实际交易。
- 使用现有 Markdown、Python、pytest 和合成评测工具；不引入 prompt 编译器、注册中心或依赖。
- 规划阶段不执行账户或模型调用；已授权的开发阶段执行纯合成模型验证，不读取真实账户，
  不推送、安装或发布。适用宿主权限仍需遵守。

## 4. 规则归属与加载协议

“唯一详细定义”允许入口和危险动作附近有一句短提醒及链接；不要求删除所有必要重复。
其他文件不得重新规定不同的预算、阈值、触发条件或错误处理。

| 规则 | 唯一详细定义位置 | 其他文件如何使用 |
|---|---|---|
| 分析/建议/模拟/历史等触发条件 | `intent-routing.md` | 入口保留条件导航；执行前按意图表决定 |
| 获取一次、执行顺序、消费 helper | `workflow.md` | 工具文档只说明接口，不复制完整流程 |
| NAV、null、完整持仓、阈值、风险重要性与组合综合 | `portfolio-analysis-policy.md` | 快照文档说明具体字段；输出文档只说明呈现 |
| 深研选择、8/2 默认预算、顾问扩围预算、机会/研究优先级、关键传导与反证 | `research-policy.md` | 入口可有一句预算摘要，不复制排序/扩围规则 |
| 来源、通用口径、隐私、不可信数据 | `evidence-policy.md` | 工具文档链接；保留必要的请求前短提醒 |
| 精确估值计算细则 | 新增 `references/valuation-policy.md` | evidence/research 在计算前强制按条件加载 |
| 授权研究能力与 skill 方法应用 | `tool-contract/core/research.md` | workflow 指向它；数据质量归 evidence 管理 |
| fatal、局部降级、重试、真正权限拒绝 | `failure-and-degradation.md` | workflow 只保留结果分支摘要 |
| 章节、表格、状态和覆盖说明的显示 | `output-contract.md` | 不重新定义选择算法或预算 |
| 明确建议请求下的方向、条件仓位、取舍与失效条件 | `recommendation-policy.md` | intent-routing 识别主动顾问意图，建议和模拟分别触发 |
| technical 的实际选择、硬上限与数据语义 | `tool-contract/core/technical.md` | research 只要求使用实际结果、披露差集 |
| 期权和可选流程的特有规则 | 现有条件 policy / optional-workflows | 继续按现有触发条件读取 |

### FR-01 默认加载

保留 D0 的文件路径和必读地位，缩短文件内容。正常综合分析先读 D0，然后调用一次
`python scripts/current_analysis.py`，再依问题加载条件文档。用户选定账户时可使用现有
`--acc-id`。多账户选择、聚合与 fatal 规则保持现状。

已在当前宿主完整加载的同版本文档直接复用；旧版本或没有完整内容不能声称已读。
文档中的普通链接是导航，不意味着递归加载所有链接。只有写明 Required/Read before
及相应触发条件的文档属于必读。被测模型不能读取评测答案或验收规则来生成报告。

### FR-02 条件加载

| 文档 | 读取时机 | 未触发时 |
|---|---|---|
| 新 `valuation-policy.md` | 准备自行计算目标价、估值区间、估值敏感性或精确估值情景之前，包括简单 P/E 模型 | 仅引用已注明来源的倍数、第三方目标价或估值背景时不强制读取 |
| `options-policy.md` 与 options contract | 持有期权或明确询问已持有期权 | 不加载期权分析规则 |
| `recommendation-policy.md` | 明确要求可行动建议或给出量化调整目标 | 一般体检不触发 |
| simulation / trades / performance / lifecycle | 各自明确意图成立 | 不读历史、不创建本地记录、不模拟 |
| `futu-public-research.md` | 使用相关 Futu 公开研究步骤 | 不作为所有研究的默认必读 |
| `references/implementation/*` | 维护、调试、审计实现时 | 日常组合分析不必读取 |

估值细则即使是条件加载，也必须在第一次相关计算之前读取；不可先出数值再补加载。
缺失细则文件时不允许凭记忆完成该计算，保留可靠事实并披露该步骤未完成。

### FR-03 移出实现细节

新增以下维护参考，均在组件目录内，随完整 skill 目录和评测工作区一起保留：

- `references/implementation/owned-state.md`：文件权限、device/inode、白名单清理步骤、
  TOCTOU 限制、同 UID 恶意并发不在保证内等原有技术说明。
- `references/implementation/snapshot.md`：source worker、静态类型查询边界、旧 schema
  兼容细节、进程预算等实现说明。
- `references/implementation/technical.md`：Decimal 精度、pivot/volume/zone 推导、
  raw-bar hash、JSON 大小预算和验证重放算法。

运行时文档仍须保留：实际命令和参数、字段/单位/日期/覆盖语义、结果不能支持的判断、
fatal/局部失败处理、清理失败保留状态并报告路径。移动说明不改变程序保证，不让模型
另写清理代码。保留“不能保证抵御同 UID 恶意并发”的简短限制及维护文档链接。

### FR-04 通用证据与估值细则拆分

evidence 保留源日期/期间/单位、未知与零、TTM 连续四季、FY1/NTM/FY2、证券/ADR身份、
共识样本与采样时点、零负 EPS、修订分母为零、宏观字段尺度、实际执行计算要求。

valuation 接收现有适用模型、FCFF/FCFE、CapEx/NWC 符号、折现和终值、EV 到股权桥接、
摊薄股数、相对估值/SOTP、区间与敏感性规则。所有原有反例与关键输入缺失限制保留。
不能把“不必默认读取”写成“不必执行这些检查”。复用现有估值方法，不新增估值引擎；
可按已有方法计算新案例的目标价和条件情景，不能把主观数字包装成已执行的模型结果。

### FR-05 深研与技术覆盖的准确说明

定义本轮最终选定深研集合 R、helper technical 实际包含的 canonical identity 集合 T。
只对 T 内且相应指标可用的记录给出技术判断；进入 T 不代表每个 timeframe/字段均完整。
ETF 仍是单个持仓；期权走现有条件路线；不同账户重复证券按当前 canonical identity
口径匹配。未识别的证券类型不得猜测为可分析股票。

| 情形 | 报告处理 |
|---|---|
| 标的在 R ∩ T 且相应数据可用 | 使用实际技术结果，保留 as-of、周期和指标缺口 |
| 标的在 R，但不在 T | 写“本次技术结果未覆盖该标的”；只有回执支持时才说明具体选择或预算原因 |
| 用户明确扩围超过 8 个深研名称 | 按请求扩围研究；技术面仍以 T 为准，不能宣称全部技术覆盖 |
| 用户点名的小仓位未入 T | 可开展其他获授权研究，并披露未取得该标的技术结果 |
| 标的在 T，但历史或某指标不足 | 说明具体数据/指标缺口；不误标成预算跳过 |
| technical 整体失败 | 所有依赖该结果的判断不可用，保留其他可靠研究与持仓表 |
| T 包含 R 以外标的 | 不因此增加深研名称或生成新推荐 |

在“重点研究”相应标的旁简短说明缺口，在“数据缺口与来源”汇总实际未覆盖名称。
不增加必填 JSON 状态或新的报告章节；不重写工具 `COMPLETE/PARTIAL/UNAVAILABLE`。
覆盖差异不触发第二次 helper、不另跑 technical、不使用其他价格源补算。
这是默认报告路径的明确限制；未来若要扩大技术能力，应另作接口与预算变更。

示例输出（合成情形）：

> 本次按要求研究 9 个标的。US.NVDA 未出现在本次技术结果中，以下只讨论已取得的
> 经营、估值与组合证据，无法给出其当前支撑/阻力区间。

只有证据证明“另外 8 个均覆盖”时才能写覆盖 8/9，不从工具硬上限推断实际数量。

### FR-07 精简指标

基础必读文本总量同时满足：空白分隔词数 ≤ 6,900；Unicode 字符数 ≤ 54,512
（基线的 70% 向下取整）。生产指令保持英语；不通过去空格、换语言、超长单行或隐藏
强制细则“优化”指标。文件数量和行数只报告，不作为质量替代指标。

计数范围是 D0 加上默认路径无条件要求读取的任何新增文件，按路径去重。如果把段落
移到一个仍然默认必读的文件，它仍计入总量。条件估值、期权和实际加载的其他 skills
单独记录读取总量；本目标不宣称每次实际分析的总 token、费用或延迟必然下降。

语义和行为门禁优先；若达不到预算，记录差距并调整方案，不能删规则或降低验收标准。
FR-08–17 中属于默认必读的新增指令计入同一预算；不得排除质量规则以达标。建议/策略的
详细要求放入已有条件文档，实际顾问路径读取量另报，不能冒充默认路径成本。

### FR-08 按组合重要性解释主要风险

在现有三个风险证据/缺口槽位内，按对本组合的决策相关性组织讨论：使用已知的仓位/共同
暴露、影响机制、时间范围或催化因素、证据可靠性，解释为何首项比其余项更值得关注。
不默认按浮亏大小、新闻热度或单个阈值排序；同一共同驱动影响多个持仓时先合并解释，
不把重复风险当成三个独立结论，不重复加总同一持仓的暴露。

报告排序属于模型对现有证据的综合。保留工具的原始 top_risks、状态和数字；按 FR-13
完成研究选择并使用既有技术计算，最后调整报告讨论顺序。不重算/覆写工具结果，不因此
递归扩大深研名单。输入不足以支持排序时明确说明，不虚构概率或“预期损失评分”。

影响程度的定性比较与可计算损失不同；没有已执行、可核验情景计算时不能写具体组合损失。
证据不足时保留缺口，不为了填三个槽位编造第三项风险。

区分结构性风险、催化事件时间窗口和小额操作管理：同一风险的财报触发窗口不自动另占
一个风险槽位；低金额但高复杂度工具须说明潜在影响，不能只因“期权/杠杆/短期”排进前三。
局部策略期限短于组合复核周期不自动等于错误，应结合用途、名义/敏感度敞口和管理安排判断。

### FR-09 把关键事实连接到组合判断

每个重点标的选择 1–2 条最影响当前判断的问题，解释相关的“事实 → 经营驱动 → 盈利或
现金流 → 市场预期/估值 → 本组合影响”。这是一条可核验的解释路径，不要求每个事实
机械写满五步；ETF/期权按其证券性质分析，不套公司经营模型。

给出关键事实的期间和来源；中间推断标明条件，缺失的环节直接说明。营收增长不自动代表
超预期，盈利改善不自动代表股价低估，价格下跌也不自动代表便宜。缺少一致预期或估值
基准时不补造该环节。精确估值继续遵守 FR-02/04，不为满足解释结构强制做完整模型。

跨持仓综合必须说明共同驱动与不同暴露；单家公司各自优秀不能证明组合分散。
定性重叠不能冒充相关系数。用户应能分清“发生了什么”“如何解释”“为何影响我的组合”。

### FR-10 用实质反证检验核心观点

每个重点标的围绕现有 2–3 个相关论点支柱，检查至少一项能实质削弱观点的证据或条件。
优先呈现已取得的相反事实，并解释它是否改变判断；“市场有波动”“行业有竞争”等通用
措辞不能算完成反证。支持与反对证据权重不必相等，不为表面平衡捏造争议。

没有取得实质反证时如实说明，并给出有依据、可观察的失效条件及相关指标/事件/期间。
阈值若来自用户或可靠来源注明出处；分析假设必须标注，不能为了可量化而随意造一个数字。
只写未来观察条件不能冒充已经完成相反事实查证。没有历史买入理由时仍用“本次研究假设”。

当输入加入重要反证时，结论应相应降低确信程度、改变风险优先级或解释为何仍保持判断；
不可仅追加一段风险提示而对核心结论不作回应。

### FR-11 提供有依据的后续观察与建议

在既有“一句话结论”和“观察”中明确当前主要判断、证据边界，以及未来哪个事实最可能
使判断改变。给出具体指标或已知事件作为复核触发；没有可靠日期时不虚构日历或自动安排任务。
多个标的共享同一观察事项可合并说明，减少重复。一般诊断的价值不以是否给出买卖动作衡量。

用户明确请求建议时，连接“建议 → 组合层依据 → 主要取舍 → 适用/失效条件”，必要时说明
维持现状为什么合理。缺量化目标不阻止有依据的定性意见；没有模拟意图/参数仍不运行模拟，
不推荐未经请求的未持有新股。反证充分或证据不足时可以保留判断，不能强迫确定方向。

稳定章节、持仓表和当前输出边界不变。上述要求写入自然段或既有小节，不新增必填评分表、
冗长工作日志或面向用户的内部推理过程；只展示关键依据和可检验的结论。

### FR-12 期限与资金用途的适配判断

区分资金兑现期限、策略持有期和报告复核窗口。已知条件直接复用；未知时用简短条件句
说明适用范围，继续提供有依据的机会判断，不启动全套问卷。仅当缺失信息实质影响具体
仓位规模/模拟时提出针对性问题。单个账户不是用户全部财富，不能猜测整体资产或现金需求。

没有已知风险预算/目标配置时，“单股不超参考阈值”“有现金和短债”只证明对应结构事实，
不能直接推出适合用户或风险很低。分别说明可用现金、流动性储备、风险资产与资金用途。
可用明确假设的简短压力计算说明量级，不能把局部线性冲击当最大损失或违约概率。

### FR-13 按风险和机会分配研究工作量

保留全部持仓表和候选来源：重要权重、前五补足、主要风险关联、用户点名。明确请求的
研究范围优先；普通诊断最多 8 个重点标的。预算不足时，以对组合的影响、判断分歧、
近期催化和资料缺口是否可能改变结论分配工作量，再用权重与 symbol 作稳定比较。
说明选择/遗漏理由，不引入面向用户的伪精确机会分数。

已确认结构简单的现金管理/短债工具可以在概览完成期限、流动性、分配及关键风险核验，
不机械占用公司深研名额；若用户点名、结构复杂或存在实质风险则进入重点研究并正常计数。
这是 prompt 层选取规则的明确调整，不改变技术选择或账户分类。ETF 身份/结构未经确认时
不能自行认定为现金等价物，更不能对其做公司 DCF。

首要风险或最强机会所依赖的标的必须有足够研究支持；若预算无法覆盖，应降低相应结论
强度并披露缺口，不只给业务标签后作强结论。公司深研覆盖率与包含储备资产的总覆盖率
分开表达。主题关联仓位不是纯主题经济敞口；主题纳入/排除口径一致，交叉主题不重复加总。

### FR-14 对金额与经济含义做交叉核验

发现数量、报价单位、合约乘数、市场价值、成本、盈亏或 Delta 换算不一致时，检查已有
源字段定义、证券身份和同次结果。工具状态 COMPLETE 不能代替经济含义核验；合约数量
乘报价是否还需要乘数必须以字段语义为准，禁止重复乘数或凭代码标签补字段。

未确认的异常标为待核验，并限制受影响金额/结论；保留权威原始值，不直接“修正”NAV
或行情。若已确认当前持仓/估值基础不可靠，仍遵守既有 fatal 规则；否则不因局部异常
中断可靠股票分析。不重读账户来验证猜测，也不把未知与真实零混淆。

测试用独立合成数字，例如 3 张、乘数 100、明确每股报价 0.02 与报告市值 0.06 的矛盾。
用户本次报告的账户标识、金额、持仓组合和快照不能被复制到提交文档或模型评测输入。

### FR-15 输出鲜明、可检验的机会判断

用户请求更进取、更有主见或主动顾问分析时，应把有证据的机会和明确取舍放进“一句话
结论”与“观察”，主动给出最值得优先考虑的 1–3 个判断。证据不足以支持数量时说明具体
原因，不凑机会；证据充分时也不能把“无法保证”“继续观察”当作完整结论。

每项说明：看好/不看好的具体对象与比较基准、关键驱动、为何是现在、兑现催化/时间范围、
主要反证与失效条件、对已有组合的增量价值。可以明确说某持仓比另一个更值得新增资金，
或某低权重持仓缺乏足够差异化贡献；这是选择性判断，不要求给每行强制 ADD/HOLD/TRIM/EXIT。

“市场低估/尚未计价/预期差”必须有可核验的估值或预期基准；没有市场共识证据时标为
本次研究假设，不虚构市场普遍看法。判断确信程度与风险承受意愿分开，不能把强观点换算
成未经依据的成功概率。仅列风险的报告与只喊看多的报告都不满足本条。

### FR-16 主动组合建议与收益风险情景

明确的主动顾问请求触发 recommendation policy。围绕最重要的取舍提供加/减/保留方向、
调整优先级、资金来源或用途、当前持有的机会成本；说明相对维持现状有什么优势及代价。
仅缺完整估值模型不能阻止有充分证据的方向性判断，关键数据缺失则只限制对应精确数值。

在用户风险/流动性约束已知时可给出目标权重或区间及其依据；未知时可给出明确假设下的
方案区间，说明它不是已完成个性化适配的结论，不自行填入用户可承受损失。现金也有流动性
与选择价值，不能默认全部现金都是拖累。具体数量和可执行性必须有对应价格、可用资金等证据。

对最有价值的机会按需比较基准、上行和下行情景，说明经营假设、估值变化、期间及兑现
条件。有数值就实际计算；情景上涨/下跌幅度不是预期收益，缺少概率依据就不报概率加权回报。
同一估值模型的敏感性情景计为一个完整估值，默认全报告最多 2 个模型，优先用于最大分歧。

公司估值/市场冲击情景与调仓模拟区分：前者不产生交易计划；后者仍只在用户明确要求
模拟并提供或确认所选量化目标时调用现有 simulate，默认一个方案。不能通过更名把多个
调仓计划当成估值敏感性。顾问提出的建议区间本身不自动触发模拟或实际交易。

### FR-17 有边界的新机会与进攻策略研究

本用户已明确希望主动提及未持有标的、事件机会和进攻策略；本次主动顾问需求因此可以
研究候选。宿主会话中已确立的这一偏好持续复用，后续一般组合请求无需重新确认；用户
明确缩小范围时遵从新范围。没有该偏好或明确机会请求的普通“检查当前持仓”仍不自动
扩展到新股或策略。意图通过自然语言及已有会话上下文识别，不新增 CLI 模式、全局偏好
配置或反复授权步骤，也不假装在没有上下文的新会话中已经知道用户偏好。

主动顾问请求的默认扩展预算：最多 2 个未持有候选、最多 1 种特殊进攻策略；已持有深研
仍最多 8 个，全报告完整估值合计最多 2 个。候选和策略可以关联同一个标的，不能借策略
另外扫描无限标的。用户指定更大范围时按已有扩围原则处理并说明实际覆盖。公开请求仍
逐一按公共标识取数，不发送私有组合、数量、账户或策略仓位信息。

每个新候选说明相对现有持仓的增量价值、为什么胜过继续持有/加仓同类标的、催化与价格
条件、风险相关性和主要反证。事件机会要有可核实日期/阶段和实际信息差，不能把日历
本身当成超额收益证据。未经核验的传闻只作待验证线索，不支持精确事件交易。

允许研究集中配置、事件交易、杠杆 ETF 或期权等进攻结构，但说明结构如何产生收益和
损失、适用期限、流动性与必要管理成本。没有可靠合约/报价/保证金等关键证据时，提供
策略机制与完成量化所缺输入，不生成伪具体合约、保证金或最大损失。现有 options 工具
只分析已持有期权，不能宣称它已验证新策略；使用适用的已有授权研究/计算能力，不改交易边界。

候选置于“观察”内的小节或紧凑比较表，与完整持仓表及持有标的深研区分。特殊策略只在
确有适用机会时提出；没有合格策略时说明为何不推荐，不以“激进”强制提高杠杆或周转。
候选不加入账户持仓或原技术结果 T；未取得的技术、相关性和风险字段不能由定性观点补造。

### 6.1 研究质量的新旧对照

以下阈值是本版提出的验收目标，尚非已取得的效果，也不代表统计显著性或投资回报保证。
验收关注给定证据下的判断质量，不使用事后价格涨跌证明当时分析正确。

**输入与版本控制：** RQ-01 在任何生产 prompt 改动前冻结旧版 B0 的完整指令、运行代码、
宿主/模型明确版本与可配置推理参数、工具目录、用户请求、账户快照、公共数据和日期。
最终新版 B1 只改变本计划允许的指令；工具实现、数据、权限、各案例明确给定的研究预算、
执行时间/输出预算相同。普通案例使用 8/2，Q09 向两个版本明确同样的候选/策略预算。
每次新会话执行，不共享另一版本的报告或模型记忆；数值计算环境一致。
如宿主无法确认同一模型版本或配置，报告比较条件不足，不宣称完成受控对照。

在生产指令编辑前冻结以下 9 个场景、评分规则及应关注/不可推断的事实范围。场景沿用
现有合成账户和公开数据 reader 的接口，只增补合成经营证据，不接真实行情。期望结果是
允许多种合理结论的证据检查表，不是单一标准文案。可使用额外小样本开发 prompt，正式
验收输入和答案不作为改写 prompt 的示例；若据其失败调参，标记为回归集并另备未用于
调参的等价验收样本，不反复使用已调参样本证明泛化改善。

| 场景 | 输入设计 | 必须能辨别的质量差异 |
|---|---|---|
| Q01 共同驱动与风险排序 | 一个显眼的单股价格下跌或小额复杂工具，另有跨大仓位的共同需求风险及财报窗口；公开价格变化与快照盈亏分开 | 是否识别组合重要性，避免把同一风险的事件窗口重复计数或将小额工具自动列首要风险 |
| Q02 好公司与价格条件 | 经营改善，同时提供可比期间估值和有来源的市场预期 | 是否区分经营质量、预期兑现和价格隐含假设，避免自动“好公司就应加仓” |
| Q03 盈利与现金转换 | 利润增长但现金转换走弱，附营运资本/会计口径和可能的时点解释 | 是否检验增长质量并保留替代解释，而非只复述利润或机械认定恶化 |
| Q04 实质反证变体 | 与 Q03 同组合/请求/基础证据，仅加入同一期、可核验的关键经营反证 | 是否调整确信程度/风险排序或合理解释不调整；不可忽略反证 |
| Q05 不足与冲突的证据 | 估值或共识期间错配、关键字段缺失，同时保留可靠经营事实 | 是否拒绝伪精确结论并完成其余有用分析，不把缺失当零或整体停摆 |
| Q06 明确请求建议 | 在有证据的组合情形询问“应如何调整”，不给量化目标 | 是否给出有依据的取舍/条件，不强问无关参数、不擅自模拟或引入新股 |
| Q07 顾问适配与经济含义 | 已知复核期但兑现期不明、简单储备资产较大、报价单位存在待核实歧义；核心快照合法 | 是否继续有用判断但限制适配/精确规模，核验单位，合理分配研究精力；不把原始数值擅自乘 100 |
| Q08 证据充分的进取型持仓建议 | 明确要求主动调整，给定合成风险/资金约束；两项机会有不同催化、估值情景和反证 | 是否提出有理由的资金优先级、条件仓位与收益风险取舍；证据充分仍只说观察应低分 |
| Q09 新候选与事件策略 | 明确要求最多 2 个新候选和 1 种进攻策略，提供有限合格公共数据及部分策略输入缺口 | 是否解释相对现有持仓的增量价值和事件预期差，完成可支持的策略分析并只限制缺失参数，不捏造合约或行情 |

每个场景两个独立重复，B0/B1 各一次，形成 18 对、36 份报告。随机并记录每对执行顺序；
编辑前保存 B0 完整输入与配置，最终成对运行时核验可比性。旧版可在冻结副本中于最终
评测阶段运行，不要求在编辑前执行。不得挑选较好的一次作为结果。
9 个现有/扩展行为回归仍独立保留；初次正式验收总计 45 次模型执行，不含开发样本和
原因明确后的必要复测。本轮规划不运行模型。

**盲评：** 对报告随机分配 A/B 标签并隐藏版本及执行顺序，由未生成该报告的评审者按同一
证据检查表评分；可用模型辅助核对，但模型自评分或自动偏好不能单独宣布通过。每个评分
必须定位到报告段落及支持/缺失证据；评分完成后解盲。模型无法看到操作者答案和评分文件。
旧版不因缺少新文件名、特定措辞或新文档读取步骤被扣研究质量分；新版路径合规另做 AC 检查。

| 维度，等权 | 满分 4 分的可观察表现 |
|---|---|
| 事实与证据准确性 | 关键主张能定位到相应来源/期间/口径，事实、假设与推断清楚，计算可核验 |
| 风险重要性 | 根据真实组合暴露和证据讨论优先级，识别共同驱动、避免重复和无依据严重性 |
| 解释深度与组合关联 | 关键传导关系有依据，指出缺失环节，把公司变化转成组合层意义 |
| 反证与判断校准 | 回应实质反证，区分当前反证和未来失效条件，不把不确定性写成确定结论 |
| 决策参考价值 | 机会/风险观点鲜明、优先级有依据，建议/新机会符合意图且有增量价值、条件和取舍，不堆信息 |

统一分档：0=缺失或严重错误；1=泛泛提及；2=部分有依据但漏关键联系；3=主要要求满足、
少量遗漏不改变结论；4=完整且清楚、无无关堆砌。各场景在冻结检查表中给出对应的 2/3/4
分证据锚点和可接受替代结论，不能只凭文风评分。报告更长或引用更多不自动加分。
在 Q08 这类证据与用户意图充分的案例，若只给风险提示/继续观察、不提出机会或取舍，
决策参考价值最高 2 分且 AC-21 不通过；Q05 真正缺数据时明确保留判断不因此扣分。
盲目看多、随意加杠杆或多给交易次数不得加分。Q09 不因拒绝编造缺失策略参数而扣分，
但必须完成已有证据支持的候选比较与策略机制分析。

**同时满足以下标准才算研究质量提升：**

1. B1 没有任何关键错误：编造支撑主结论的事实/来源/指标，重大口径或算术错误，忽略已给
   的核心反证并作确定性主张，账户/交易/隐私越界。硬错误不能靠其他维度平均分抵消。
2. 每份报告为五维平均分；同一场景先对两个重复取平均，九个场景再等权汇总。B1 总分
   ≥3.0/4，且相对 B0 提高 ≥0.4 分；五个维度各自的跨场景平均分均不下降。
3. 至少 6/9 个场景（至少三分之二）的平均总分严格提高；任一场景不得下降超过 0.25 分。分别报告两个重复
   的差值与离散情况，小样本不作统计显著性宣称。
4. AC-01–16、AC-18–23 和既有行为/账户门禁同时满足。合法执行但漏答按评分规则计分；执行环境失败
   使该对不可比较，整体验收标未完成，不删除困难场景缩小分母。缺一对不能声称全量通过。

如果 B0 已接近满分、无足够改善空间，仍不得降低门槛或声称已证明提升；可报告工程改进
完成、研究改善未证明，并另提更有辨别力的评测修订。冻结后更改阈值/场景必须显式留痕，
重新建立双方可比基线，不能依据结果反向选题或修改答案。

质量评测定义与输入在实施阶段落到 `evals/research-quality.md` 和
`evals/quality-fixtures/cases.json`。操作员证据检查表留在前者、模型只获得后者中被明确选取
的请求和公共 fixture 数据，经现有准备流程放入隔离工作区；两者不整目录复制给模型。
不新建生产研究服务或模型评判平台。

## 7. 边界与完成标准

- 始终：先记录实际基线、保存已有工作区变更、逐项迁移规则、按切片验证、报告真实覆盖。
- 若要扩大范围：新增技术能力/接口、生产 schema/算法、依赖、默认持久化或发布另立变更；
  不在本次精简中顺带实施。既有授权的正常本地文档与验证工作无需重复确认。
- 禁止：外发真实账户、修改上游审计文件、解除只读、删除失败证据、降低既有测试门禁。

完成条件：AC-01–23 都有可核验结果。分别报告工程整理、行为不退化、研究质量提升三个
状态；没有对照证据就不能声称研究提升，即使词数与测试均通过。缺少实际模型执行时只
报告“结构/本地回归完成，行为与质量验收未完成”。交付规则迁移、读取量、覆盖差异、
完整盲评结果及回滚说明。

回滚只还原本轮指令、参考和必要评测变更；不回滚并行账户/交易代码，不处理历史账户数据。
新增维护参考随对应引用一起回退，避免断链。无需账户数据迁移或存储升级。

当前没有阻断规划的未决参数。提高技术上限或将点名透传到 helper 是后续能力需求，
不属于本版承诺。
