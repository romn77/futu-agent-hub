# Host-provided policy context feasibility

日期：2026-10-16。用户明确允许验证宿主加载方案，扩展原有仅修改Skill/评测的范围；
账户、交易、风险、技术、期权引擎及生产schemas仍保持不变。起点`c8ef242`，产品为R2。
此前R2/R3结果与历史AC-17保持原结论。

## Boundary

先做可选、仅合成数据的宿主原型：宿主装配当前规则正文及SHA-256，经既有Codex CLI
stdin一次提交，记录后续文件访问。原参考文件仍可读，不删文件、不禁用读取、不伪造
command_execution，也不改变必读内容或用报告自述替代证据。验证可行性不等于生产上线。

本地CLI 0.154.0确认支持stdin、JSONL、read-only及ephemeral；官方
[non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode)确认同一路径。
不用替换内建系统指令的model_instructions_file，不修改用户全局配置或认证。

## Contract

- evals/policy_context.py：默认12份完整规则加显式声明的条件路径，限定白名单内的Markdown；
  禁止任意文件、路径穿越和符号链接。保留原UTF-8正文、逐文档字节数/哈希和确定性bundle ID。
- 提交前重新核对工作区源版本、完整文档集合和实际payload字节；缺失、重复、变更、截断、
  篡改或不支持的路径均失败。摘要或只有哈希不能代替正文。
- 宿主提交回执单列，命名为已验证的CLI输入，不声称远端模型读取/记忆或服务端revision。
  观察器仍单独记录真正文件读取，原必读文件检查不改写；新宿主检查组合完整提交证明和
  原有非加载执行检查。模型自述不能生成宿主回执。
- 对已预加载路径，每次后续完整文件读取都算重读（包括第一次cat）；未预加载的必要
  条件文件允许首次读取，第二次才算重读。失败/部分读取单列，不能因零完整重读就当通过。
  合成目录中四份白名单研究方法同样按未预加载文件计数；未知Markdown不能借同条命令中
  另一个完整正文的匹配获得通过。统计来自工具输出，不等于操作系统文件访问追踪。
- 不增加运行时服务、账户调用或永久缓存。先验证可用的上下文传递，不声称工具强制禁止重读。

## Bounded verification

1. 本地正反例：完整提交、正文/哈希/原文件/请求变更、漏文档、非法路径、symlink、
   已注入后第一次完整读取、重复日志、未注入条件首读、模型自报、真实账户/非fixture脚本拒绝。
2. 已知allocation_fork失败输入，两种模式各两次，共4份开发报告；输入/生产规则字节相同，
   只改变宿主上下文提交方式。顺序预登记，同gpt-6-astra/medium、600秒/8MiB预算和工具。
3. 两份宿主报告均须章节/字段/采集边界通过、无完整重读或不可核验规则读取；独立代理
   检查关键事实和研究质量，不得因减少读取而丢失规则。失败保留，不能挑报告或无限重试。
4. 若试点通过，再用R3准备但从未运行的三个独立新输入各做一份宿主验证，要求同样的
   执行/内容门槛。该三份仅作绝对可行性检查，不宣称新旧质量改善或统计泛化。
5. 共最多7份报告，无环境错误不重试。报告真正输入/缓存/输出token，默认文件成本与
   条件成本分开；不以零文件重读推断token或费用下降。

独立代理复核按已授权的skill行为验证流程执行，评分锁定后汇总。全部证据保留新目录，
不回写旧报告。工程、宿主交付、模型复用、内容质量、生产适用性分别报告。
本阶段不接真实账户，不安装、推送或合并；可选原型验证完成后再判断生产集成范围。
