# Spec 机构配置与风格调研

模块：`institutional-style`。状态：设计草案。依赖[共享 SEC 证据](SPEC-sec-evidence.md)。

## 1. 目标与解释范围

从**用户指定的机构列表**出发，对齐季度末持仓，识别跨机构的增减仓、集中与分歧、行业／主题配置变化，产出值得继续研究的问题。

结论必须限定为“本次披露样本中的配置变化线索”。不把样本代表成全市场，不从季度末差异还原真实交易过程，不宣称这些线索已经验证具有预测收益的能力。

13F 是机构管理人的报告，可能汇总多个账户或策略；不能将申报主体自动等同于一只基金或某位经理的个人观点。它有披露滞后，且不包含空头仓位，不能独立重建完整净敞口。[SEC 13F FAQ](https://www.sec.gov/rules-regulations/staff-guidance/frequently-asked-questions-about-form-13f)

## 2. 用户机构列表

### 2.1 配置契约

用户提供明确文件路径，或在会话中提供等价列表。只有用户要求保存／更新列表时才持久写入。设计阶段不预选真实机构，默认模板如下：

```yaml
schema_version: 1
universe_id: my-managers
managers: []
```

每项支持：

| 字段 | 规则 |
|---|---|
| `cik` | 必填，归一化为十位数字字符串，保留前导零 |
| `display_name` | 用户显示名称；与 SEC 法律名称并列核验，不用于实体匹配 |
| `enabled` | 默认 true；禁用项保留配置但不采集 |
| `tags` | 用户组织标签；不能自动当作经验证的风格分类 |
| `strategy_group` | 可选，值与来源同时记录；未验证则 unknown |
| `family_id` | 可选，用于父子管理人／同集团关系，需来源与范围确认 |
| `notes` | 可选私人备注，仅本地使用，不发送研究服务 |

同 CIK 重复项报配置冲突；不同名称对应同 CIK 不能重复计票。只给名称且能唯一核实身份时可解析并回显 CIK；多义名称必须由用户选择。空名单不运行扫描，也不自动填入知名机构。

### 2.2 名单版本与采样单位

运行记录 `universe_id`、`universe_version`、启用 CIK 集合及配置变化说明。`universe_version` 根据启用 CIK 与已核验的独立采样关系计算；显示名／私人备注修改只改变配置修订号，不制造样本成员变化。hash 仅用于内部复现，不把配置原文／私人备注放到外部请求。

主观察单位是已核验的独立管理主体；同集团重复报告、共同投资决定或委托报告关系要先核对。无法证明独立时可报告 filing 层观察，但不将其计为多个独立机构支持同一信号。

机构分组由名单中的已核验元数据决定；系统不根据一季持仓自动认定其“价值基金”或“主动管理”。缺失分组可做全样本描述，不能声称跨策略共识。被动与多策略管理人可以保留，但在有可靠分类时分别展示。

用户后来添加／删除机构后，不将名单变化当成配置变化。跨运行对比必须使用共同样本，或完整重算同一新名单的历史，且明确“当前名单历史观察”，不声称它就是历史时点选定的样本。

## 3. 请求、期间与预算

`InstitutionalResearchRequest`：机构配置引用、`target_period`、`knowledge_cutoff`、`quarters`（默认 4）、主题／证券过滤、数据预算、保存意图。

- 默认 target_period 为标准披露期限已结束的最近自然季度末；依据有效申报日历处理周末／节假日，不使用“今天减 45 天”替代完整期限判断。
- 用户指定尚在披露期的季度时照常做已披露样本，标为 preliminary，不能静默退回上一季度，也不能把未报机构当作空仓。
- 四个季度快照最多形成三个相邻变化；至少两期才有变化，一期只能描述持仓。
- `knowledge_cutoff` 继承共享契约；不得把今天发现的补充披露用于更早时点的可得性判断。
- 运行前列明启用机构数、季度数和预计采集量；名单较大时分批处理同一范围，不静默选择前 N 家。

拟议默认执行预算：每机构最多检查 100 份相关申报元数据；整体 10 分钟、200 MiB 下载上限，最多两个读取任务并发，另受服务限流约束。预算触顶保留已完成部分与未完成名单；用户可显式扩大。不得用截取持仓前 N 行来节约分析成本。

## 4. 有效季度持仓构建

### 4.1 选择与完整性

按 `(manager_cik, report_period)` 找到 cutoff 允许的原始申报及修订。显式区分 13F-HR、13F-HR/A、13F-NT／组合报告及其关联管理人。Notice 不是空持仓；无法重建委托／组合关系时保留缺口，不计入要求完整性的比较。

优先使用 SDK 绑定具体 accession 的原始信息表和封面／摘要。现有 ownership MCP 的 top-N、自动 latest 和自动前期比较只能用于浏览或核对；提高 limit 不能替代期间与修订验证。[EdgarTools 13F 对象](https://edgartools.readthedocs.io/en/latest/guides/thirteenf-data-object-guide/)

每份文件检查：实际解析行数与申报 entry total、归一化金额与该份文件 summary total、读取范围、下载及解析状态。差异记录原因；金额按申报／SDK 单位语义处理，不能统一乘以 1,000。对账容差基于明示舍入精度，不按结果大小任意放宽。

### 4.2 修订

按同季度的 amendment sequence、公开时间和来源组织：

- 原始报告建立基线。
- RESTATEMENT 作为完整更正替换此前对应有效集合。
- NEW HOLDINGS 增补此前未列示的记录，不替换整份持仓。
- 连续多个修订逐一应用；序号冲突、未知类型、范围不清或无法确认替换语义时暂停该季度的完整比较。
- 去重的是同一 accession／同一原始行被重复读取；不能只按 CUSIP 或数值相同就删除不同文件中的合法增补记录。疑似重复增补要核对，不能静默相加或丢弃。
- 保密解除或遗漏补报注明实际历史报告期间和首次公开时点，不解释为本季新买入。

RESTATEMENT 与新增持仓修订具有不同效力，必须按封面处理。[SEC FAQ 58b–58d](https://www.sec.gov/rules-regulations/staff-guidance/frequently-asked-questions-about-form-13f)

修订后的有效集合保留全部贡献 accession、每行来源、被替代关系和归一化过程。最终总额来自有效集合；不能拿最后一份增补文件的 summary 当整份组合总额。

### 4.3 证券身份与原始字段

保留 issuer name、class、CUSIP、FIGI（如有）、put/call、SH/PRN、数量、原始金额／单位、归一化 USD 金额、investment discretion、other manager、voting authority 与源行定位。

跨期匹配使用经过确认的证券身份及类别。Ticker 只是显示字段，不能作为唯一主键。普通股、ADR、不同股类、看涨／看跌期权、PRN 金额类不能因 CUSIP／issuer 相同而混加。汇总前保留原始行及经理关系；本机 SDK 的友好 holdings 表会聚合部分原始维度，不能直接替代原始行审计。

拆股、合并、分拆、ADR 比率变化及 CUSIP 变更先建立有日期和证据的映射。确定的纯拆股调整数量；复杂重组未能建立可比关系时标为不可比，不能伪造新建／退出。

### 4.4 缺失不等于零

只有两期均完整覆盖声明的公开范围、身份可比且无已知保密／遗漏／修订缺口时，某期未出现才可作为“该公开表未报告此证券”的零，用于公开持仓变化分类。

输出 NEW_REPORTED／NO_LONGER_REPORTED（中文“首次出现／不再报告”）；在上述条件满足且无已知其他解释时可概括为“新建／退出线索”。不得声称已证明全部真实账户从零建仓或完全清仓。

## 5. 单机构变化计算

### 5.1 计算范围

V1 主信号使用已确认可比的普通股／ADR。ETF 作为独立工具类别展示，不穿透后再与直接股票重复计入；期权、PRN 及不支持品种只列覆盖，不构造 Delta、净方向或统一股数。

记录三种分母：原始申报总额、可识别普通股／ADR 总额、两期均可比的分析子集总额。所有比例标明使用哪一个，**均不能命名为基金总 AUM 或基金全部资产权重**。

### 5.2 数量变化与市值变化

对证券 i，令 `q0*` 为调整到本期单位的前期数量，`q1` 为本期数量：

```text
delta_q = q1 - q0*
quantity_change_pct = delta_q / abs(q0*)   （仅 q0* > 0）
```

前期零时增长率为不适用，首次出现单列。数量不明或公司行动未解决时输出 null。

对两期都有持仓、同币种、同证券且金额／数量有效的普通股：

```text
p0* = V0 / q0*
p1  = V1 / q1
quantity_effect_proxy = (q1 - q0*) * p1
repricing_effect      = q0* * (p1 - p0*)
V1 - V0               = quantity_effect_proxy + repricing_effect
```

`p` 是申报期末隐含每股金额，用于对账与描述；检查其是否合理。quantity_effect_proxy 是以期末价格衡量的数量变化代理，**不是实际买卖金额、净资金流或收益贡献**。退出证券若无合格本期价格，则不计算该分解；不能令 p1=0。新出现证券没有 p0，单独说明。

### 5.3 排除价格漂移的配置变化

对于每家机构的两期证券并集 S，先形成能够获得本期参考价格、身份和公司行动均已核验的共同计算集合 S*。两期数量都按本期单位计量：

```text
w1_i        = q1_i * p1_i / sum(j in S*, q1_j * p1_j)
w0_fixed_i  = q0*_i * p1_i / sum(j in S*, q0*_j * p1_j)
allocation_shift_i = w1_i - w0_fixed_i
```

同价重估只移除价格漂移，不识别资金申赎、被动再平衡或经理动机。全部持仓同比例增加时配置比例可不变，仍可报告数量增加。

本期未持有证券的 p1 需其他合格季度末价格，不能从零持仓反推。缺少时移出 S*，同时报告两期原始金额覆盖率及排除名单；不得静默改分母。任一分母为零／未知时停止该指标。普通申报权重变化仍可展示，但标为包含价格影响。

### 5.4 集中与重叠

可展示公开分析范围内的 top-N 权重、HHI、共同持仓数量和权重重叠；明确分母与覆盖。它们是样本公开持仓结构指标，不是完整风险暴露、相关系数或真实市场拥挤度。

## 6. 从变化到行业、主题与风格

### 6.1 分类

| 维度 | V1 方法 | 缺失时行为 |
|---|---|---|
| 行业 | 同一有版本的行业体系，一家公司一个主分类 | unknown，不把 SIC 随意改称 GICS |
| 业务主题 | 有申报／业务证据支持的多标签，记录关联理由 | 只列已证实关联；多主题比例不可相加当总暴露 |
| 规模 | 相同参考时点的市值，记录股类／发行人归集方法 | 不用股价高低代替市值 |
| 成长／价值 | 单独的可选量化分类配置，必须声明指标、数据时点、比较宇宙和分桶规则 | 没有合格配置就不输出该风格结论 |
| 防御／周期、质量等 | 有明确分类依据的描述性标签或经过定义的因子 | 不根据行业名称或单个 PE 临时猜测 |

风格标签并非 13F 原生字段。V1 不硬编码“低 PE 就是价值”“科技就是成长”等判断。用户机构 tags 与证券风格标签分别记录。

为识别配置变化，比较两期时冻结同一版本的证券分类；分类迁移另行展示。历史研究需要当时可得的分类输入。当前分类回看历史只能称为“按当前分类重述”，不能伪装为时点还原。

### 6.2 跨机构聚合

对于主题／行业 k，将同一机构各证券 allocation_shift 汇总为 `d_mk`。单一互斥行业可加总；多标签主题分别计算，禁止把多个主题再加总为完整组合。

对已确认独立、期间一致且分类／数值可比的机构集合 M：

```text
increase_count = count(d_mk > epsilon)
decrease_count = count(d_mk < -epsilon)
unchanged_count = count(abs(d_mk) <= epsilon)
net_breadth = (increase_count - decrease_count) / len(M)
median_shift = median(d_mk for m in M)
```

主视角为机构等权，避免最大申报人主导；同时展示分组、分子／分母、反向机构和覆盖。可选按公开申报规模加权作为敏感性对照，不能标为真实 AUM 权重。

`epsilon` 仅过滤数值噪声，默认比例值 1e-8，不作为投资重要性阈值。报告用基点显示 median_shift，并保留完整计算精度；极小变化不因方向一致就称为“显著轮动”。

连续多个季度的变化比较使用固定共同机构集合；每个相邻期可用样本不同的结果单独呈现，不能拼成同一样本连续趋势。缺失机构不归为 unchanged。

### 6.3 信号状态与排序

V1 不生成黑箱综合分数或上涨概率。每条信号展示广度、幅度、持续性、反向证据和数据质量，采用可解释的三态：

- `OBSERVATION`：可报告局部事实，但样本、可比性或连续性不足。
- `RESEARCH_LEAD`：符合下列研究选题门槛，值得进一步核验。
- `UNAVAILABLE`：核心数据无法支撑该项计算或判断。

默认选题门槛是工程筛选配置，不是统计显著性或交易阈值：

1. 至少五个独立管理主体可比，且覆盖启用独立样本的至少 80%。
2. 每个纳入机构两期 S* 的金额覆盖均至少 90%（各期 S* 原始金额／该期全部已识别普通股与 ADR 金额）。分类覆盖分别按两期同价重估后的 S* 金额衡量，有明确该维度分类的比例均至少 90%；其余机构不计票并报告。无法确认整体证券类型／总额的机构不能仅用已识别小子集满足门槛。
3. 同方向机构比例至少 60%，median_shift 与该方向一致。
4. 若称“持续性线索”，至少两个相邻季度变化在同一共同样本上满足方向条件；单次只能称当季线索。

小于五家机构的用户名单仍完整运行，输出观察与逐机构证据，不假装满足广泛共识。样本相关、缺失非随机等限制随结论保留；门槛通过不等于总体代表性或因果证明。

默认最多展开五条研究线索，按状态、持续期数、绝对 net_breadth、绝对 median_shift、稳定分类 ID 排序；方向无偏好。不足五条不凑数。报告同时保留最重要的分歧和覆盖缺口，不能只展示同向买入叙事。

## 7. 输出与交接

### 7.1 报告

1. 结论与时间：报告季末、cutoff、披露滞后及 provisional 状态。
2. 用户机构池与覆盖：启用／成功／缺失名单、名单版本、独立性与分组状态。
3. 主要变化：行业／主题／可用风格的方向、广度、幅度、持续性及反例。
4. 机构与证券证据：具体来源、数量变化、价格影响及不能比较的部分。
5. 研究优先级：最多五条问题，为什么值得研究，验证路径与推翻条件。
6. 来源、被排除范围和未完成工作。

报告可以得出“本次没有足够证据支持共同风格变化”。不得为满足版式制造轮动判断。

### 7.2 `StyleSignal` 契约

`signal_id`、`universe_version`、`report_periods`、`knowledge_cutoff`、`classification_version`、`analysis_scope`、`eligible_manager_ids`、覆盖分母、direction、net_breadth、median_shift_bps、consecutive_intervals、支持／反向机构、证券贡献、`evidence_refs`、状态、limitations、`research_questions`。

字段是可验证的公开研究结果，不包含用户账户。信号交给公司研究时保留“待验证原因”；交给 analyst 时先在本地匹配持仓，不把私有组合返回给机构数据源。

线索只推荐后续工作，不自动消耗公司深研／估值预算。用户明确请求联合工作流时才执行后续任务，并分别报告已完成阶段。

## 8. 实现与验证

Skill 负责研究组织和输出；共享 SDK 辅助程序负责原始公开取证；确定性 Python 函数负责修订合并、身份匹配、差分、分母和信号计算。LLM 负责提出问题、阅读解释和综合判断，不凭自然语言印象计算跨机构信号。

用 Python `Decimal`／明确精度的数值处理金额与数量；将原始行、归一化、比较和解释分开。字段命名采用 `snake_case`；函数输入／输出可空语义一致。外部输入进入时验证，纯计算不得联网或读取账户。

预期新增机构 Skill、配置模板、共享纯计算及 fixtures。当前不存在可执行的 institutional-style CLI。拟议实现后的纯测试命令：

```bash
"$SEC_RESEARCH_TEST_PYTHON" -m pytest "Futu API Skills/sec-research-core/tests/test_changes.py" "Futu API Skills/sec-research-core/tests/test_signals.py" -q
```

验收见 [INST-01 至 INST-18](ACCEPTANCE.md#4-机构配置与风格调研)。V1 必须先证明全量、修订、单位、证券身份及可比计算正确，再进行风格解释；解析输出漂亮或 MCP success=true 不构成通过。

## 9. 非目标

不自动选机构，不将名单修改为推荐组合，不启动每日实时扫描，不推断真实交易成本／时点／意图，不构造未披露现金或空头，不以 13F 期权行推算净 Delta，不自动跟单。信号收益能力需要另行定义时点严格的回测和样本外评估，本版不宣称验证。
