# Spec 独立公司研究

模块：`company-research`。状态：设计草案。依赖[共享 SEC 证据](SPEC-sec-evidence.md)。

## 1. 目标与用户故事

让用户从一家公司或一个具体经营问题出发，形成有原始证据、反证和后续观察条件的研究判断。没有 Futu 账户、没有 OpenD 或未授权账户读取时，本流程仍可研究公开公司资料。

用户可以：

- 研究一家公司的业务、财务质量与主要争议。
- 深入核验一条机构调研线索，例如“多家机构增持该公司是否有经营依据”。
- 比较公司前后披露，判断经营逻辑、风险或资本配置发生了什么变化。
- 明确请求同行比较或估值；这些条件工作不自动扩大普通研究。

## 2. 输入与范围

`CompanyResearchRequest`：

| 字段 | 规则 |
|---|---|
| `company` | 公开 ticker／CIK／公司名称；先确认发行人与证券类别 |
| `questions` | 用户问题或至多三个本次研究问题 |
| `knowledge_cutoff` | 继承已有研究链截止时点；新任务默认开始时点 |
| `mode` | `focused` 或 `comprehensive`，由问题范围路由 |
| `lead_refs` | 可选机构线索；只作为假设来源，不作为经营结论 |
| `peer_scope` | 用户指定或本次明确声明的可比公司，默认最多两家用于比较 |
| `valuation_requested` | 默认 false；价格吸引力是核心争议时明确转入估值方法 |

默认 comprehensive 覆盖一家公司、最新合格年报／季报、四个连续单季基线及必要事件。focused 只回答明确问题，不能标记为完整公司深研。独立研究无固定八家公司上限；用户请求多家公司时明确列出范围与预算，不继承或消耗不存在的组合持仓槽位。

默认最多二十份相关文件元数据、六份文件的正文深读、每份只读必要章节；四单季取证所需追加文件可解释后扩大。预算是运行成本约束，不是完整性证明；未完成的要求留在报告中。

## 3. 工作流程

### 3.1 定义问题

确认公司身份和研究时点；将“研究这家公司”收敛为 2–3 个可被证据检验的问题。没有历史投资记录时，称为“本次研究假设”，不编造用户持有理由。

来自 13F 的线索需要明确“机构持仓变化已经观察到，变化原因尚待验证”。研究问题应落到经营、现金流、资本配置或估值，不把机构名望当作结论。

### 3.2 建立资料与财务基线

先定位相关申报，再固定 accession。美国公司按实际文件使用 10-K／10-Q／8-K；外国发行人按 20-F／40-F／6-K 等实际披露组织，不要求不存在的 10-Q。

基线包括业务构成、收入与利润趋势、现金转化、资产负债和资本配置；选择对当前问题有解释力的指标。期末现金与现金流分开，管理层指引与共识分开，分部收入与公司总收入分开。

四季度资料不足时保留真实期间，不能拼接半年度数据或累计数伪造单季序列。公司不适用普通企业指标时采用行业适用方法，例如银行、保险、REIT，说明口径。

### 3.3 针对性下钻

按关键问题读取业务、MD&A、风险、附注和相关公告。例：利润现金转化 → 应收／合同资产、收入确认、营运资本及现金流；扩产 → CapEx、承诺采购、产能与需求；杠杆 → 到期结构、约束条款、现金及租赁。

只将已核实的变化写入结论。相邻季度的章节省略、模板变化、会计分类变动不自动等于经济变化。

### 3.4 检验与反证

对每个主要论点列出支持证据、实质反证、解释与可观察的失效条件。没有找到实质反证时说明搜索范围与未解问题，不能用泛泛风险凑对称观点。

同行用于解决具体可比问题，必须对齐业务、财年、币种、会计口径和指标定义。同行比较不自动生成买入候选。

### 3.5 市场与估值条件层

SEC 提供历史申报与管理层披露。行情、历史估值分布、分析师预期修正、宏观及新闻由已有合格公开能力补充。

当结论涉及“价格是否有吸引力”时，明确研究价格和时点；目标价／敏感性必须执行实际计算并采用适用估值方法。独立流程复用可获得的估值 skill 与政策，不把历史财务摘要称为完整 DCF。若经 analyst 调用，则严格继承其估值预算与已加载政策。

### 3.6 收敛为结论

输出当前最有证据支持的判断、关键分歧、影响路径和下一次应关注的事件／指标。研究结论可以明确偏积极或偏消极，不要求机械买卖标签。个性化仓位建议转回 analyst，并遵循其账户及意图规则。

## 4. 输出契约

独立报告采用以下内容顺序，篇幅按问题深度调整：

1. 结论、研究问题与截止时点。
2. 公司如何赚钱，以及 2–3 个主要经营驱动。
3. 已核验的财务基线：期间、币种、口径和关键变化。
4. 主要论点：证据 → 解释 → 反证 → 判断。
5. 同行／估值／机构持仓背景，只呈现已触发并完成的部分。
6. 失效条件、下一步验证、来源和局部缺口。

同一宿主内可交接 `ResearchFinding[]` 和 `ResearchLead[]`，字段遵循共享契约。将完整研报交给 analyst 不是必需动作；它可直接复用问题相关事实及引用。交接不包含账户标识、持仓数量或私人投资历史。

## 5. 失败与降级

- 身份歧义：不能继续公司事实归属；给出已查到的候选身份供选择。
- 一份文件不可读：继续其他可靠证据，将受影响问题标为缺口。
- 财务序列不可比：不输出 TTM／增长率，正文研究仍可继续。
- 章节截断：补读关键位置；仍缺失时限制相应判断。
- 共识或行情缺失：经营研究有效，市场定价／预期差结论受限。
- 无账户访问：不是本流程失败，不触发 doctor 或账户采集。

## 6. 实现落点与风格

新增 `Futu API Skills/company-research/SKILL.md`、短小的方法及输出引用、行为评测。共享 SEC 数值规则只引用一次，不复制成另一套财务算法。

Skill 主文件只放触发方式、核心步骤、范围和条件引用。深读附注、估值、跨期差异等按需加载。沿用现有宿主提供的方法能力，不创建 skill-to-skill RPC 或固定一组可用工具的假象。

不存在可执行的 company-research CLI。用户通过自然语言触发 Skill；拟议公共取证命令由共享模块承担。实现后的行为评测应复用现有 eval harness 的实际可用接口，参数在实现任务中验证，不在本 spec 虚构命令。

## 7. 成功条件

对应 [CMP-01 至 CMP-05](ACCEPTANCE.md#3-独立公司研究)。至少验证普通美国公司、外国发行人、正文截断、财务期间不完整、与主论点相冲突的披露。研究必须能在不读取账户的情况下完成；实质反证必须影响判断或得到明确回应。

本版不自动制作完整投行报告、电子表格、历史 thesis 档案或交易建议。用户另行请求时才扩展交付物。
